# CRN-M-02 — Барабаны, блоки, полиспасты
# D2 Practice v1
## Прикладная механика: FBD, геометрия, навивка и статус модели

---

# Зачем эта практика

D2 проверяет не способность назвать термин, а способность провести один и тот же инженерный маршрут через более реальную канатную систему:

```text
SYSTEM / MODE
→ ROPE PATH
→ CONTACT NODES
→ LOCAL Ti
→ CHOOSE BODY
→ DRAW FORCES
→ GEOMETRY / SPOOLING STATE
→ MODEL STATUS
→ SOURCE / OEM IF REQUIRED
```

Главное отличие от D1: один физический канат больше не даёт тебе бесплатного права писать один и тот же `T` везде. Равенство локальных натяжений, квазистатика, почти окружная кинематика и совпадение геометрического радиуса с плечом момента — это **допущения модели**, которые должны быть доказаны для текущего вопроса.

Practice не содержит численных `D/d`, размеров канавок, допустимых углов, коэффициентов КПД, допускаемых напряжений/давлений, discard limits или разрешений на изменение реального механизма.

---

# Общий формат ответа

Для каждого кейса используй один каркас:

1. **SYSTEM / MODE** — какое тело/узел и какой режим рассматриваются?
2. **ROPE PATH** — как реально проходит канат?
3. **CONTACT NODES** — где он взаимодействует с блоком, барабаном, закреплением, соседним слоем?
4. **LOCAL `Ti`** — какие рабочие метки нужны; доказано ли их равенство?
5. **FBD** — для какого тела рисуются силы?
6. **GEOMETRY / SPOOLING** — какие направления, линии действия, радиусы или состояния контакта важны?
7. **MODEL STATUS** — `SIMPLE`, `QUALITATIVE APPLIED` или `SOURCE / OEM REQUIRED`?
8. **BOUNDED CONCLUSION** — что можно утверждать и чего нельзя?

Карманные guards:

```text
ONE ROPE ≠ PROVEN ONE T EVERYWHERE
BLOCK FBD ≠ ROPE FBD
NO SLIP ≠ UNIVERSAL v_rope = ωr
LAYER RADIUS ≠ UNIVERSAL MOMENT ARM
OBSERVATION ≠ ACCEPT / DISCARD VERDICT
TERM MATCH ≠ DEFINITION / REFERENCE GEOMETRY MATCH
QUASI-STATIC ≠ ACTUAL DYNAMIC LOAD
```

# Кейс A — Один канат, три локальных состояния
## Segment-tension bookkeeping

Условный путь:

```text
барабан → блок A → блок B → dead end
          T1       T2       T3
```

Известно только, что это один непрерывный канат. Никаких данных о потерях, трении, ускорении и контактной механике не дано.

### Задача

1. Объясни, зачем вообще вводить `T1`, `T2`, `T3`, если канат физически один.
2. Какие равенства между ними **не доказаны** исходным условием?
3. Какие дополнительные допущения могли бы позволить учебно принять равенство части или всех `Ti`?
4. Какой model-status следует дать до таких допущений?
5. Сформулируй bounded conclusion без выдуманного коэффициента потерь.

### Ловушка

```text
ОДИН ФИЗИЧЕСКИЙ КАНАТ
≠
ДОКАЗАНО T1 = T2 = T3
```

# Кейс B — Одна точка контакта, две FBD
## Action / reaction discipline

Канат огибает блок. На первой схеме ты рассматриваешь **BLOCK**. На второй — локальный участок **ROPE** в той же зоне контакта.

### Задача

1. Для `FBD: BLOCK` подпиши, кто действует на блок.
2. Для `FBD: ROPE` подпиши, кто действует на канат.
3. Объясни отношение между парой контактных сил по третьему закону Ньютона.
4. Почему нельзя взять стрелку из `BLOCK FBD`, оставить направление и использовать её в уравнении для `ROPE FBD`?
5. Если ты сменил выбранное тело, какое действие должно быть первым: новая формула или перестройка стрелок?

### Ловушка

```text
СМЕНИЛ ТЕЛО
→ СТАРЫЕ СТРЕЛКИ БОЛЬШЕ НЕ ПРИНАДЛЕЖАТ НОВОЙ FBD
```

# Кейс C — Тот же `T`, другая геометрия
## Reaction direction without scalar-angle shortcut

Сравни два учебных положения одного блока. Для чистоты сравнения **явно задано** `T1 = T2 = T`.

```text
Положение 1               Положение 2
    │                          ↗
    O                          O
    │                          │
```

### Задача

1. Для каждого положения выбери `FBD: BLOCK`.
2. Нарисуй качественно две силы каната на блок по локальным касательным.
3. Объясни, почему одинаковые величины `T` не гарантируют одинаковую результирующую нагрузку на опору.
4. Что именно изменилось: масса груза, величина `T`, направления сил или всё сразу?
5. Почему из рисунка нельзя назначить допустимый угол или допустимую нагрузку на подшипник?
6. Выдай model-status.

### Ловушка

Не вводи численную формулу реакции через «угол между ветвями», пока определение угла и нужная геометрия не заданы.

# Кейс D — Окружная кинематика барабана
## `r_k` and a deliberately simple model

Для **идеализированного учебного случая** известно:

- рассматривается окружное движение поверхности барабана;
- контакт локально почти окружной;
- существенной винтовой/осевой составляющей пути нет;
- проскальзыванием пренебрегаем;
- `r_k = 0,25 м`;
- `ω = 2,0 рад/с`.

### Задача

1. Что означает `r_k` в этом вопросе?
2. Найди окружную скорость поверхности.
3. При каких перечисленных допущениях эту величину можно использовать как приближение скорости каната?
4. Какие из этих условий нужно перепроверить, если канат начал переходить между витками или слоями?
5. Почему полученное число не является допустимой скоростью конкретного механизма?
6. Выдай model-status для учебного случая и отдельно для реального механизма без паспорта/OEM.

### Ловушка

Число здесь — **учебная кинематика**, не equipment limit.

# Кейс E — `NO SLIP`, но укладка винтовая
## Helical-spooling kinematic trap

Канат укладывается по барабану с заметным осевым продвижением за оборот. Скольжение в контакте условно отсутствует. Коллега говорит:

> «Раз no slip, скорость каната точно `ωr`».

### Задача

1. Что в этой фразе доказано словом `no slip`, а что не доказано?
2. Почему окружная скорость поверхности и скорость каната вдоль его фактической траектории не обязаны быть одной и той же скалярной величиной?
3. Какое дополнительное геометрическое описание нужно до точной кинематической связи?
4. Можно ли на D2 дать качественный вывод без численной формулы?
5. Выдай model-status.

### Ловушка

```text
NO SLIP
≠
ЛЮБАЯ ТРАЕКТОРИЯ КАНАТА СТАЛА ОКРУЖНОЙ
```

# Кейс F — Радиус слоя и плечо момента
## `r_k` versus `r_m`

В первом учебном положении сила каната `T = 12` условных единиц действует касательно, а её перпендикулярное плечо относительно оси `r_m = 0,30` условных единиц длины.

Во втором положении величина силы та же, но линия действия заметно отклонена; известен только видимый радиус текущего слоя `0,30`.

### Задача

1. Для первого положения найди момент силы относительно оси в простой касательной модели.
2. Какой параметр отвечает за этот расчёт — `r_k` или `r_m`?
3. Можно ли во втором положении автоматически оставить тот же момент только потому, что видимый радиус слоя не изменился?
4. Что нужно знать о линии действия силы?
5. Что может совпасть численно в простой геометрии, но не становится одним параметром по определению?
6. Выдай model-status для обоих положений.

### Ловушка

```text
ВОПРОС ПРО ДВИЖЕНИЕ → r_k
ВОПРОС ПРО МОМЕНТ → LINE OF ACTION + r_m
```

# Кейс G — Сначала состояние навивки, потом вердикт
## Spooling-state recognition

Даны четыре наблюдения:

**G1.** Канат лежит рядом с соседним витком в одном слое без видимого перехода.

**G2.** Канат поднимается с нижнего слоя на следующий.

**G3.** В многослойной навивке участок проходит через crossover-зону.

**G4.** Видно боковое слежение/контакт, но точная геометрия, допуски и состояние каната не измерены.

### Задача

Для каждого G1–G4:

1. назови состояние наблюдения;
2. перечисли контактные особенности, которые становятся важными;
3. отдели **наблюдение** от **механизма возможного влияния**;
4. скажи, можно ли уже вынести accept/discard/repair verdict;
5. укажи, когда требуется точный стандарт, инструкция/OEM или осмотр по установленной процедуре.

### Ловушка

```text
CROSSOVER / SIDE CONTACT OBSERVED
≠
АВТОМАТИЧЕСКИ «ДОПУСТИМО» ИЛИ «БРАК»
```

# Кейс H — Маршрут изменили, груз тот же
## Load-path redistribution

Имеется механизм, в котором положение направляющего блока изменили на эскизе. Масса груза и условная величина тягового усилия в сравнении сохранены, но направления двух ветвей у опоры изменились.

### Задача

1. Какие элементы D2-route нужно перестроить после изменения положения блока?
2. Можно ли оставить старую реакцию опоры только потому, что груз не изменился?
3. Какие FBD должны быть построены заново?
4. Какие величины можно оставить как учебные допущения, а какие направления нужно перечитать из новой геометрии?
5. Почему одинаковая идеальная кратность не доказывает эквивалентность load path двух реальных схем?
6. Что требуется до физической перестановки блока на реальном ПС?

# Кейс I — Ускоренный подъём
## Quasi-static stop condition

Для блока ранее была построена квазистатическая карта:

```text
R_support→block + F_rope→block + F_other = 0
```

Теперь известно, что рассматриваемая сборка имеет существенное ускорение во время переходного режима.

### Задача

1. Почему старое равновесие нельзя выдавать за фактическую динамическую нагрузку?
2. Что изменилось в выборе модели?
3. Какие силы из старой FBD не исчезают только потому, что появилась динамика?
4. Какой новый тип баланса требуется концептуально?
5. Имеет ли D2 право без исходных данных назначить коэффициент динамичности или максимальную нагрузку?
6. Выдай model-status.

### Ловушка

```text
КВАЗИСТАТИЧЕСКАЯ СХЕМА
≠
ДИНАМИЧЕСКИЙ РАСЧЁТ С НУЛЕВЫМ УСКОРЕНИЕМ ПО ПРИВЫЧКЕ
```

# Кейс J — «Угол вроде тот же»
## Definition / reference-geometry / source trap

На реальном механизме измерен некоторый угол между видимой ветвью каната и выбранной линией. В другом документе найден численный предел для термина, переведённого как «угол набегания/отклонения». Не проверены:

- точное определение величины;
- от какой reference geometry она отсчитывается;
- применимость документа к этому механизму;
- конфигурация барабана/блоков;
- редакция OEM/паспорта.

### Задача

1. Можно ли сравнить два числа только по похожему названию угла?
2. Что нужно доказать до такого сравнения?
3. Какие три уровня нужно разделить: термин, определение/геометрия, нормативный limit?
4. Какой model-status должен быть выдан сейчас?
5. Сформулируй bounded conclusion, не назначая новый предел.

### Ловушка

```text
TERM MATCH
≠
DEFINITION MATCH
≠
REFERENCE-GEOMETRY MATCH
≠
APPLICABLE LIMIT
```

# Кейс K — Один успешный подъём и режим эксплуатации
## Duty / classification context

Два механизма один раз подняли одинаковый груз. Про первый известно, что он работает редко и с небольшим числом циклов. Второй делает множество повторных циклов и имеет иной спектр нагрузок/перемещений.

Коллега говорит:

> «Оба один раз подняли одинаковый вес — значит по механике они эквивалентны и выбор механизма одинаков».

### Задача

1. Почему один максимальный успешный подъём не описывает весь service context?
2. Какие категории эксплуатационного контекста D2 обязан помнить качественно?
3. Даёт ли D2 право самостоятельно назначить группу классификации без полного применимого расчёта/исходных данных?
4. Что можно утверждать как качественный engineering context?
5. Какой source-level нужен для реального selection/classification решения?

### Ловушка

```text
«ВЫДЕРЖАЛ ОДИН РАЗ»
≠
«КОРРЕКТНО ВЫБРАН ДЛЯ РЕЖИМА ЭКСПЛУАТАЦИИ»
```

# Что Practice сознательно не проверяет

Этот этап не является:

- расчётом прочности барабана/оси/подшипника;
- подбором каната, блока или барабана;
- нормативной проверкой `D/d`;
- расчётом допускаемого fleet/deflection angle;
- назначением КПД или потерь конкретного механизма;
- процедурой браковки каната;
- разрешением на изменение запасовки/крепления/геометрии;
- заменой паспорта, OEM manual или применимого стандарта.

Следующий отдельный этап — **Practice Reasoning v1** — покажет корректные траектории рассуждения и типовые failure modes, но не превратит эти кейсы в один механический answer key.
