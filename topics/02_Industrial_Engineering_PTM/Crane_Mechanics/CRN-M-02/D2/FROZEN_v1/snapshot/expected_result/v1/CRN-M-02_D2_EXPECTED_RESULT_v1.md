# CRN-M-02 — Барабаны, блоки, полиспасты
# D2 Expected Result v1
## Наблюдаемый профиль прикладной механики канатной системы

---

# Назначение

Expected Result фиксирует не то, что ученик прочитал про барабаны и блоки, а то, **что он способен доказуемо сделать на новой прикладной схеме** после D2.

D2 не превращает ученика в конструктора крана и не даёт права назначать численные пределы по памяти. Зрелый результат D2 включает способность вовремя остановить модель и честно выбрать один из статусов:

```text
SIMPLE
QUALITATIVE APPLIED
SOURCE / OEM REQUIRED
NOT YET DEMONSTRATED
```

Правильный `SOURCE / OEM REQUIRED` или `NOT YET DEMONSTRATED` является успешным результатом, если ученик показывает, **какой именно факт/геометрия/источник отсутствует** и почему без него следующий вывод был бы недоказан.

Численные `D/d`, размеры канавок, fleet/lead/deflection limits, реальные коэффициенты эффективности, допустимые напряжения/давления, критерии браковки, назначение режима/классификации и разрешение на изменение конкретного ПС **не входят в D2 Expected Result без точного применимого источника или OEM/паспорта**.

---

# Краткая формула результата D2

После D2 обучающийся способен пройти цепочку:

```text
SYSTEM / MODE
↓
ROPE PATH
↓
CONTACT NODES
↓
LOCAL T1 / T2 / T3 ...
↓
CHOOSE FREE BODY
↓
FORCE DIRECTIONS / REACTION LOGIC
↓
GEOMETRY + SPOOLING STATE
↓
KINEMATIC OR MOMENT MODEL — ONLY IF SUPPORTED
↓
MODEL STATUS
↓
SOURCE / REFERENCE-GEOMETRY CHECK WHEN REQUIRED
↓
BOUNDED CONCLUSION / FIELD AUTHORITY BOUNDARY
```

Если условия меняются, ученик **перестраивает затронутую часть модели**, а не переносит старый ответ по инерции.

---

# ER-D2-01 — Восстанавливает систему, режим, путь каната и контактные узлы

## Наблюдаемое поведение

До формул ученик фиксирует:

- что является анализируемой системой;
- какой режим/состояние рассматривается;
- полный rope path в пределах доступной схемы;
- барабан, блоки, точки закрепления и другие контактные узлы, влияющие на силовой путь.

Он не начинает анализ с одного понравившегося блока, не потеряв остальную систему.

## Evidence output

Минимум:

```text
SYSTEM / MODE:
...

ROPE PATH:
...

CONTACT NODES:
1. ...
2. ...
3. ...
```

## Не считается достигнутым

- анализ отдельной детали без доказанного контекста пути;
- пропуск контактного узла, который меняет направление/передачу силы;
- формула до реконструкции исходной системы.

---

# ER-D2-02 — Ведёт локальный bookkeeping натяжений и не приравнивает `Ti` без модели

## Наблюдаемое поведение

Ученик способен обозначить локальные участки как `T1`, `T2`, `T3`, ... и воспринимает эти символы как **состояния/неизвестные bookkeeping-переменные**, а не как утверждение о скачках или постоянстве натяжения.

Равенство вида:

```text
T1 = T2
```

допускается только если ученик явно назвал модель/допущения, которые это поддерживают.

## Evidence output

`LOCAL-TENSION MAP`:

```text
SEGMENT 1 → T1
SEGMENT 2 → T2
SEGMENT 3 → T3

EQUALITIES ASSUMED/DEMONSTRATED:
...
```

## Критический признак

Фраза «это один физический канат, значит везде один `T`» не является достаточным обоснованием D2.

---

# ER-D2-03 — Выбирает free body до стрелок и сохраняет ownership сил

## Наблюдаемое поведение

Перед каждой FBD ученик явно пишет, **какое тело изолировано**:

```text
FBD: BLOCK
```

или:

```text
FBD: ROPE
```

или другое конкретно названное тело.

После смены тела он перестраивает стрелки и не смешивает в одной диаграмме действие каната на блок с действием блока на канат.

## Evidence output

- `FREE BODY:`;
- отдельная схема/список сил;
- подпись владельца каждой силы или однозначное направление относительно выбранного тела.

## Не считается достигнутым

- стрелки без названного free body;
- сохранение тех же стрелок после перехода от `BLOCK` к `ROPE`;
- суммирование сил, принадлежащих разным FBD.

---

# ER-D2-04 — Объясняет изменение реакции через векторную геометрию

## Наблюдаемое поведение

Если направления ветвей изменились, ученик понимает, что реакция узла может измениться даже при неизменной величине выбранных локальных натяжений.

Он рассуждает через направления сил/векторную сумму и **не обязан** применять случайно запомненную скалярную формулу через угол.

## Evidence output

`REACTION LOGIC`:

```text
FREE BODY: ...
FORCE DIRECTIONS: ...
WHAT CHANGED: geometry / direction
REACTION CONSEQUENCE: qualitative ...
```

## Claim limit

Численный предел угла, допустимая реакция или разрешение конкретной геометрии отсюда не следуют.

---

# ER-D2-05 — Использует `r_k` только для доказанной кинематической модели барабана

## Наблюдаемое поведение

Для простой почти окружной учебной геометрии ученик способен связать угловое движение барабана и окружную скорость через кинематический радиус `r_k`.

Он отдельно проверяет, действительно ли скорость каната в рассматриваемом направлении можно приравнять окружной скорости поверхности.

При винтовой/осевой составляющей, сложной геометрии или недостатке данных ученик не объявляет универсально:

```text
v_rope = ωr
```

## Evidence output

`KINEMATIC CARD`:

```text
QUESTION: motion / speed
r_k = ...
MODEL CONDITIONS: ...
MODEL STATUS: ...
RESULT OR STOP: ...
```

## Сильный признак D2

`NO SLIP` сам по себе не считается доказательством произвольной пространственной формулы пути каната.

---

# ER-D2-06 — Отличает `r_m` от `r_k` и строит момент из линии действия силы

## Наблюдаемое поведение

Для вопроса о моменте относительно оси ученик сначала определяет силу и её line of action, а затем — соответствующее плечо `r_m` или векторный момент.

Он не подставляет автоматически видимый радиус текущего слоя только потому, что этот радиус использовался в кинематическом вопросе.

## Evidence output

`MOMENT CARD`:

```text
QUESTION: moment about axis
FORCE: ...
LINE OF ACTION: ...
r_m / vector moment basis: ...
MODEL STATUS: ...
```

## Не считается достигнутым

- `r_k = r_m` без доказательства геометрии;
- момент через «радиус слоя на рисунке» без line-of-action reasoning.

---

# ER-D2-07 — Распознаёт состояние навивки до механизма и вердикта

## Наблюдаемое поведение

Ученик сначала классифицирует наблюдаемое состояние, например:

- соседние витки одного слоя;
- переход между слоями;
- crossover-зона;
- боковое слежение / контакт;
- другое описанное состояние, если оно однозначно видно из данных.

Только затем он формулирует возможный механический смысл и границы вывода.

## Evidence output

`SPOOLING STATE CARD`:

```text
OBSERVED STATE: ...
MECHANICAL SIGNIFICANCE: qualitative ...
WHAT IS NOT PROVED: ...
NEXT EVIDENCE NEEDED: ...
```

## Blocking candidate

Наблюдение `crossover` или бокового контакта не должно автоматически превращаться в `DISCARD`, `ACCEPT`, «неправильный угол» или разрешение на ремонт.

---

# ER-D2-08 — Перестраивает load-path модель после изменения маршрута или геометрии

## Наблюдаемое поведение

Если блок, точка закрепления, направление ветви, состояние барабана или другая существенная геометрия изменились, ученик заново проверяет:

- rope path;
- contact nodes;
- локальные `Ti`;
- выбранные FBD;
- направления сил;
- реакции;
- применимость прежнего model status.

Он не считает, что неизменный груз или одинаковая идеальная кратность автоматически сохраняют нагрузки на опоры.

## Evidence output

`DELTA / REBUILD CARD`:

```text
CHANGED INPUT: ...
MUST REBUILD: ...
MAY REMAIN: ...
NEW MODEL STATUS: ...
```

---

# ER-D2-09 — Отличает квазистатическую модель от динамической задачи

## Наблюдаемое поведение

Ученик способен назвать допущение квазистатики и распознать ситуацию, где существенное ускорение/замедление требует другого уровня модели или источника.

Он не представляет `ΣF = 0` как фактическую динамическую нагрузку только потому, что ускорение «кажется небольшим».

## Evidence output

`DYNAMIC BOUNDARY`:

```text
QUASI-STATIC ASSUMPTION: ...
ACCELERATION / TRANSIENT PRESENT: yes/no/unknown
MODEL STATUS: ...
REQUIRED NEXT STEP: ...
```

## Успешный stop-condition

Если данных для динамической модели нет, корректный `SOURCE / OEM REQUIRED` или `NOT YET DEMONSTRATED` является сильным ответом.

---

# ER-D2-10 — Проверяет термин, определение и reference geometry перед численным limit

## Наблюдаемое поведение

Когда появляется численный угол/геометрический критерий, ученик не ограничивается совпадением слов `fleet angle`, `lead angle`, `deflection angle` или похожего термина.

Он требует доказать:

1. точное определение величины;
2. от каких линий/плоскостей она отсчитывается;
3. применимость источника к рассматриваемому оборудованию/режиму;
4. редакцию/статус источника, если это требуется для решения.

## Evidence output

`SOURCE / REFERENCE-GEOMETRY CHECK`:

```text
TERM: ...
DEFINITION / REFERENCE GEOMETRY: ...
APPLICABLE SOURCE: ... / NOT AVAILABLE
NUMERIC LIMIT AUTHORITY: SUPPORTED / NOT SUPPORTED
```

## Критический признак

Похожее название величины не является лицензией переносить найденный численный предел.

---

# ER-D2-11 — Использует duty/classification как контекст, не как выдуманный коэффициент или полномочие

## Наблюдаемое поведение

Ученик понимает, что режим эксплуатации, циклы, спектр нагрузок и классификационный контекст могут влиять на выбор/оценку компонентов.

При этом он не делает скачок:

```text
"тяжёлый режим" → "я знаю нужный коэффициент"
```

без применимого source-backed расчётного правила.

Он также отделяет механическое понимание от права изменить реальную запасовку, барабан, блок или режим эксплуатации.

## Evidence output

`DUTY / AUTHORITY BOUNDARY`:

```text
KNOWN CONTEXT: ...
WHAT IT MAY AFFECT: ...
WHAT IS NOT DERIVED: ...
SOURCE/OEM/PASSPORT NEEDED FOR: ...
```

---

# ER-D2-12 — Выбирает честный model status, выдаёт bounded conclusion и переносит D2 на незнакомый кейс

## Наблюдаемое поведение

На схеме, которой не было в Practice A–K, ученик самостоятельно выполняет полный D2 workflow и выбирает один из статусов:

```text
SIMPLE
QUALITATIVE APPLIED
SOURCE / OEM REQUIRED
NOT YET DEMONSTRATED
```

Статус должен следовать из доступных данных, а не из желания обязательно получить число.

## Evidence output

Полный `D2 EVIDENCE PACKAGE` на unseen case плюс bounded conclusion:

```text
WHAT IS DEMONSTRATED:
...

WHAT IS NOT DEMONSTRATED:
...

MODEL STATUS:
...

NEXT EVIDENCE / SOURCE:
...

FIELD AUTHORITY BOUNDARY:
...
```

## Критерий transfer

Успех на знакомых A–K **недостаточен**.

Verification должен дать новую компоновку/описание, где нельзя решить задачу простым узнаванием сюжета.

---

# Минимальный D2 evidence package

Verification Rubric должен уметь потребовать и оценить минимум:

1. `SYSTEM / MODE`;
2. `ROPE PATH`;
3. `CONTACT-NODE MAP`;
4. `LOCAL-TENSION MAP`;
5. `FREE BODY + FORCE OWNERSHIP`;
6. `GEOMETRY / SPOOLING STATE`;
7. `KINEMATIC CARD` или `MOMENT CARD`, если вопрос этого требует;
8. `MODEL STATUS`;
9. `SOURCE / REFERENCE-GEOMETRY CHECK`, если заявляется нормативный/оборудовательный вывод;
10. `BOUNDED CONCLUSION / FIELD AUTHORITY BOUNDARY`.

Для кейса, где SIMPLE-модель не доказана, отсутствие численного расчёта **не является дефектом**, если stop/escalation доказан правильно.

---

# Transfer requirement

Known-case performance alone is insufficient.

Verification должен включить минимум один **unseen applied case**, который требует нескольких D2-компетенций одновременно, например:

- новый rope path;
- несколько контактных узлов;
- выбор local `Ti`;
- named FBD;
- изменённая геометрия или состояние навивки;
- необходимость выбрать model status.

Кейс не должен быть механической копией A–K с заменёнными числами.

---

# Challenge / delta requirement

Чтобы проверить не память готового ответа, после первичного решения Verification должен изменить **один существенный вход**, например:

- выбранное free body;
- направление ветви;
- положение/маршрут блока;
- состояние навивки;
- наличие ускорения;
- определение/reference geometry из источника.

Ученик должен показать:

```text
WHAT CHANGED
→ WHAT MUST BE REBUILT
→ WHAT MAY REMAIN
→ NEW MODEL STATUS
```

Сильный D2-признак — способность **изменить собственный предыдущий вывод**, когда новые данные действительно меняют модель.

---

# Candidate blocking failures для Verification Rubric

Следующий stage должен определить тяжесть и non-compensable статус минимум для следующих ошибок.

## BF candidate 1 — One-rope-equal-T shortcut

Ученик объявляет все локальные `Ti` равными только потому, что это один физический канат.

## BF candidate 2 — FBD ownership collapse

Ученик смешивает действие/противодействие или суммирует стрелки разных free-body diagrams.

## BF candidate 3 — Universal `ωr`

Ученик применяет `v_rope = ωr` к произвольной винтовой/пространственной траектории без доказанной геометрии.

## BF candidate 4 — Layer-radius-as-moment-arm

Ученик подменяет `r_m` видимым радиусом слоя без line-of-action proof.

## BF candidate 5 — Observation-to-verdict leap

Crossover/side contact/другое наблюдение автоматически превращается в accept/discard/repair verdict без применимого критерия.

## BF candidate 6 — Terminology-only numeric authority

Численный предел импортируется только из-за похожего названия угла/величины без определения и reference geometry.

## BF candidate 7 — Quasi-static-as-dynamic authority

Квазистатическое равновесие выдаётся за фактическую динамическую нагрузку при наличии существенного ускорения/переходного режима.

## BF candidate 8 — Classification-factor invention

Из словесного duty/classification context придумывается конкретный коэффициент, selection result или equipment verdict без источника.

## BF candidate 9 — Comprehension-to-field-authority leap

Понимание механики схемы превращается в разрешение менять реальную запасовку/блок/барабан/режим без паспорта/OEM/процедуры и полномочий.

---

# Что D2 Expected Result сознательно НЕ подтверждает

Успешный D2 не означает, что ученик уже может самостоятельно:

- назначить численный `D/d`;
- выбрать размеры канавки;
- назначить допустимый fleet/lead/deflection angle;
- вычислить реальную эффективность канатной системы без соответствующей модели;
- проверить прочность барабана/реборды;
- назначить допустимое контактное давление;
- выдать браковочный/ремонтный verdict по одному визуальному признаку;
- классифицировать конкретный ПС по неполному набору данных;
- изменять запасовку или конструкцию реальной машины.

Для этих задач нужен следующий уровень компетентности и/или точный применимый источник, паспорт/OEM, процедура и соответствующие полномочия.

---

# Итог D2 Expected Result v1

D2 считается содержательно освоенным не тогда, когда ученик запомнил несколько формул, а когда он способен:

```text
SEE THE SYSTEM
→ MAP THE PATH
→ NAME LOCAL STATES
→ CHOOSE THE BODY
→ OWN THE FORCE ARROWS
→ READ GEOMETRY / SPOOLING
→ USE rk OR rm ONLY FOR THE RIGHT QUESTION
→ CHOOSE AN HONEST MODEL STATUS
→ REBUILD AFTER A DELTA
→ STOP AT THE SOURCE / AUTHORITY BOUNDARY
```

Это и есть контракт для следующего этапа — Verification Rubric.
