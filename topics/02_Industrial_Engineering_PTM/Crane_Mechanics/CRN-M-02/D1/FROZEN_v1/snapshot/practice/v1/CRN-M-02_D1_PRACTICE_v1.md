# CRN-M-02 — Барабаны, блоки, полиспасты
# D1 Practice v1
## Чтение запасовки, карта сил и идеальная модель

---

# Зачем эта практика

D1 проверяет не запоминание формулы, а последовательность мышления:

```text
ПУТЬ КАНАТА
→ КАРТА ПЕРЕДАЧИ СИЛ
→ ПРОВЕРКА ПРОСТОТЫ СХЕМЫ
→ n-МОДЕЛЬ, ЕСЛИ ОНА ДОКАЗАНА
→ ИДЕАЛЬНАЯ МЕХАНИКА
→ ГРАНИЦА РЕАЛЬНОЙ МАШИНЫ / ДОКУМЕНТОВ
```

Нельзя начинать ответ с `n = ...`, пока не показано, откуда это `n` взялось.

В Practice нет таблиц допустимых D/d, радиусов канавок, углов набегания, прочности барабана, коэффициентов реальной эффективности или разрешённых схем конкретного крана. Если кейс пытается вытянуть из тебя такой ответ — правильная часть решения должна обозначить границу D1.

---

# Общий формат ответа

Для каждого кейса, где есть схема запасовки, используй один каркас:

1. **Движущаяся сборка** — что выбрано как одно движущееся тело?
2. **Концы каната** — где барабан/тяговый конец и где закреплённый конец; движется ли точка закрепления?
3. **Путь каната** — пройти канат от конца до конца.
4. **Карта сил** — отметить каждую часть каната или закрепление, через которое натяжение действует на выбранную движущуюся сборку.
5. **Simple-model check** — можно ли честно свести схему к простому `n`?
6. **Идеальная модель** — только если шаг 5 пройден.
7. **Field boundary** — что из ответа нельзя переносить на реальный кран без паспорта/OEM/применимого документа?

Допустимые ответы на шаге 5:

```text
SIMPLE n-MODEL SUPPORTED
SIMPLE n-MODEL NOT YET DEMONSTRATED
ESCALATE BEYOND D1
```

# Кейс A — Детали ещё не полиспаст
## Component roles / rope path

Перед тобой условная канатная система:

```text
БАРАБАН → O → O → ЗАКРЕПЛЕНИЕ
           \___/
        часть блоков
```

Из рисунка известно только:

- один из блоков закреплён на конструкции;
- другой может двигаться вместе с крюковой подвеской;
- точка закрепления конца каната показана, но не подписано, движется ли она;
- барабан выбирает/выдаёт канат.

### Задача

1. Объясни роль барабана без численных норм.
2. Объясни, почему число нарисованных блоков ещё не даёт кратность.
3. Назови минимум три факта, которых не хватает, чтобы считать `n`.
4. Укажи, какой элемент схемы нужно определить первым.
5. Дай статус simple-model check.

### Ловушка

```text
КОЛИЧЕСТВО БЛОКОВ
≠
КОЛИЧЕСТВО ПОДДЕРЖИВАЮЩИХ СИЛОВЫХ СВЯЗЕЙ
```

# Кейс B — Неподвижный блок не создаёт магию
## Fixed-sheave trap

Учебная схема:

```text
      O  ← блок, неподвижный относительно груза
     / \
тяга   |
       |
      [W]
```

Одна ветвь идёт от блока к грузу. Другая — тяговый конец.

### Задача

1. Выбери движущуюся сборку.
2. Пройди путь каната.
3. Построй карту передачи силы на груз.
4. Определи, сколько силовых связей каната поддерживают груз в этой простой модели.
5. Реши, даёт ли наличие неподвижного блока само по себе идеальный выигрыш в силе.
6. Объясни, что блок здесь меняет даже в случае отсутствия выигрыша.

### Ловушка

```text
ЕСТЬ БЛОК
≠
n > 1
```

# Кейс C — Простой подвижный блок
## Rope path → force map → n

Учебная вертикальная схема:

```text
неподвижное закрепление ●
                      \
                       \
                        O  ← подвижный блок
                       / \
                      /   \
                 к барабану [W]
```

Считай, что:

- закрепление не движется вместе с грузом;
- подвижный блок и `W` образуют одну движущуюся сборку;
- обе поддерживающие части каната вертикальны;
- натяжение в них одинаково;
- трением и потерями пренебрегаем.

### Задача

1. Выполни все семь шагов общего формата.
2. Выведи символически связь между `W`, `T` и `n`.
3. Если `W = 10` условных единиц силы, найди идеальное `T`.
4. Объясни одним предложением, почему этот ответ не является расчётом реального усилия в канате конкретного крана.

# Кейс D — Четыре вертикальные силовые связи
## Ideal mechanical advantage / kinematics

Для учебной задачи уже доказано следующее:

- одна движущаяся блоковая сборка;
- четыре вертикальные части одного каната передают ей одинаковое натяжение `T`;
- закрепления концов не добавляют других силовых связей с движущейся сборкой;
- простая `n`-модель применима;
- трения и потерь нет.

### Задача

1. Определи `n`.
2. Запиши идеальную связь `W` и `T`.
3. Если грузовая сборка поднимается на `0,60 м`, сколько каната должна выбрать идеальная модель?
4. Если скорость каната `0,80 м/с`, какова идеальная скорость грузовой сборки?
5. Назови минимум три причины, почему эти отношения нельзя автоматически объявить фактическими параметрами реального механизма.

### Ловушка

Числа в этом кейсе — **учебная кинематика**, а не нормативные ограничения оборудования.

# Кейс E — Канат заканчивается на движущейся сборке
## Moving dead-end trap

Схема описана словами:

```text
барабан
→ верхний неподвижный блок
→ подвижный блок
→ второй верхний неподвижный блок
→ закреплённый конец каната НА движущейся блоковой сборке
```

Все участки, влияющие на вертикальную поддержку, на рисунке выглядят почти вертикальными.

Коллега быстро говорит:

> «Внизу один подвижный блок, вокруг него видно две ветви. Значит n = 2».

### Задача

1. Покажи путь каната.
2. Отдельно перечисли точки, через которые канат передаёт силу движущейся сборке.
3. Объясни, почему закреплённый конец нельзя отбросить как «просто конец каната».
4. Скажи, можно ли назначить `n` до построения полной карты сил.
5. Если после карты сил простая скалярная модель всё же окажется допустимой, что именно должно войти в подсчёт поддерживающих силовых связей?
6. Дай статус simple-model check **до** и **после** требуемого разбора.

### Ловушка

```text
DEAD END
≠
ZERO FORCE
```

# Кейс F — Схема, которую D1 не обязан «побеждать»
## Multi-body / equalizing stop condition

На рисунке:

- две подвижные блоковые сборки;
- один уравнительный элемент;
- канат связывает обе сборки;
- часть ветвей меняет направление при относительном движении сборок;
- неясно, какая длина каната изменяется при перемещении каждой сборки отдельно.

Начальник просит:

> «Просто посчитай все вертикальные линии и скажи кратность».

### Задача

1. Объясни, почему просьба преждевременна.
2. Укажи, какой шаг алгоритма D1 ломается первым.
3. Перечисли признаки, по которым simple `n`-model не доказана.
4. Что можно честно сделать на D1 до эскалации?
5. Какой статус simple-model check должен быть выдан?
6. Что потребуется для дальнейшего разбора: новая силовая схема, кинематическая связь, документация — или всё перечисленное?

### Ловушка

```text
СЛОЖНАЯ СХЕМА
≠
«НАДО ПРОСТО СЧИТАТЬ АККУРАТНЕЕ»
```

# Кейс G — Путь и скорость платят за выигрыш в силе
## Ideal reciprocity

Для простой учебной схемы уже подтверждено `n = 3` и применимость идеальной модели.

### Задача

1. Если движущаяся сборка проходит `0,40 м`, сколько каната должно быть выбрано/выдано в идеальной модели?
2. Если канат движется со скоростью `0,90 м/с`, какова идеальная скорость движущейся сборки?
3. Объясни физический смысл отношений без фразы «система создаёт энергию».
4. Если реальное измерение не совпало с идеальным отношением, назови минимум четыре категории причин, которые нужно проверить до вывода о неисправности.
5. Какие из этих причин D1 может назвать концептуально, но не квантифицировать без дополнительных данных?

### Ловушка

```text
ВЫИГРЫШ В СИЛЕ
→
ПРОИГРЫШ В ПУТИ / СКОРОСТИ
```

а не бесплатное увеличение работы.

# Кейс H — «Мы поняли схему, значит можно переставить канат»
## Field-authority boundary

Ты корректно прочитал фотографию/эскиз реального крана:

- восстановил видимый путь каната;
- выбрал движущуюся крюковую подвеску;
- построил карту сил;
- для изображённого положения получил правдоподобную простую `n`-модель.

После этого коллега предлагает:

> «Теперь всё понятно. Давай переставим канат на соседний блок — кратность останется такой же».

В наличии нет:

- утверждённой схемы запасовки конкретного исполнения;
- паспорта в открытом перед тобой виде;
- OEM manual;
- подтверждения геометрии барабана/блоков/каната для альтернативного пути;
- формального разрешения на изменение конфигурации.

### Задача

1. Раздели выводы на две колонки:
   - `DIAGRAM COMPREHENSION`;
   - `FIELD CONFORMANCE / AUTHORITY`.
2. Что ты действительно доказал анализом рисунка?
3. Чего ты **не** доказал?
4. Какие документы/полномочия нужны до изменения реальной запасовки?
5. Почему одинаковое идеальное `n` не доказывает эквивалентность двух реальных схем?
6. Сформулируй bounded conclusion в 2–4 предложениях.

### Ловушка

```text
ПОНЯЛ МЕХАНИКУ
≠
ПОЛУЧИЛ РАЗРЕШЕНИЕ МЕНЯТЬ КОНФИГУРАЦИЮ
```

# Самопроверка перед сдачей

В каждом кейсе проверь:

- я сначала выбрал движущуюся сборку?
- я нашёл оба конца каната?
- я различил путь каната и карту сил?
- я не потерял moving dead end?
- я не посчитал неподвижный блок как «магический множитель»?
- я доказал применимость simple `n` до формулы?
- я не применил `nT = W` к наклонной/сложной схеме без обоснования?
- я не превратил идеальную модель в реальный расчёт оборудования?
- я обозначил, где нужен паспорт/OEM/применимый документ?
