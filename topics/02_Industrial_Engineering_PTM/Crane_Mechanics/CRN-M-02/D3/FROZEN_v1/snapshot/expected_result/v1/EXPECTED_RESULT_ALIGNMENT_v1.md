## Minimum evidence outputs

Verification should make visible:

1. `CAUSAL QUESTION / CASE BOUNDARY`;
2. `OBSERVED SIGNATURE + DATA ORIGIN / MAPPING`;
3. `SYSTEM / MODE / TIME WINDOW`;
4. `PRESENT STATE / HISTORY SPLIT`;
5. `CAUSAL MAP`;
6. competing `HYPOTHESIS CARD`s;
7. `PREDICTIONS + WOULD BE UNEXPECTED`;
8. `EVIDENCE MATRIX`;
9. `OBSERVABILITY CHECK` before negative evidence;
10. `NEXT DISTINGUISHING DATA`;
11. relevant confounder/dynamic rebuild;
12. `ASSUMPTIONS + UNKNOWN REGISTER`;
13. `MODEL STATUS + HYPOTHESIS-SPACE LIMIT`;
14. `SOURCE / METHOD / AUTHORITY CHECK`;
15. `BOUNDED CONCLUSION`;
16. explicit update after challenge evidence.

## Coverage rationale

- Practice A–L spans the complete D3 causal-analysis spine without embedding worked solutions.
- Practice Reasoning provides non-exclusive strong paths rather than one mandated root cause per case.
- ER-D3-01…12 are directly traceable to lesson guards and known A–L evidence.
- ER-D3-13 intentionally cannot be closed by A–L because transfer and adaptive updating require an unseen context.
- `PLAUSIBLE — DISTINGUISHING DATA REQUIRED`, `SOURCE / OEM / SPECIALIST REQUIRED` and `NOT YET DEMONSTRATED` are legitimate successful outcomes when evidence/method/authority is insufficient.

## Unseen transfer requirement

Known-case performance is insufficient.

Verification must include at least one unseen causal case that combines several of:

```text
ambiguous signature
+ geometry/contact/spooling candidate
+ duty/history candidate
+ dynamic/transient uncertainty
+ data-quality / mapping risk
+ incomplete evidence
+ source/method/authority boundary
```

The case must not be a trivial renaming of Practice L.

## Mandatory evidence-update challenge

After the learner commits to an initial model status, Verification supplies a meaningful new datum or changed assumption.

Accepted challenge families include:

- an expected signature is absent, with observability information supplied;
- an apparent rope-section/node mapping is corrected;
- a transient event is added to history;
- a second simultaneous maintenance change is revealed;
- the same signature appears in another state;
- measurement coverage/sensitivity is revised;
- an assumed source/method applicability condition is withdrawn.

The learner must update:

```text
EVIDENCE MATRIX
→ UNKNOWN REGISTER
→ RELATIVE H SUPPORT
→ MODEL STATUS
→ BOUNDED CONCLUSION
```

## Candidate blocking failures

Verification Rubric must define severity/non-compensability for at least:

1. BF-D3-01 closed-world causal closure;
2. BF-D3-02 non-detection falsification without observability;
3. BF-D3-03 `H_data` collapse;
4. BF-D3-04 dynamic unknown erased / `not measured = zero`;
5. BF-D3-05 sensitivity-as-causal-identification;
6. BF-D3-06 before/after single-cause proof;
7. BF-D3-07 evidence-role collapse;
8. BF-D3-08 source-exists authority leap;
9. BF-D3-09 unknown/assumption erasure;
10. BF-D3-10 single-story analysis;
11. BF-D3-11 failure to update after challenge.

## D3 / D4 boundary

D3 verifies causal discrimination and bounded model-status discipline.

Formal method selection, model validation, quantitative sensitivity/error analysis and proof-model comparison remain D4 work when the case requires them.

## Claim/source boundary

Expected Result introduces no new normative threshold, proof coefficient, load combination, dynamic factor, fatigue/remaining-life number, acceptance/discard criterion or equipment-specific intervention authority.

D1/D2 remain immutable prerequisites, not sources of automatically transferable numeric authority.
