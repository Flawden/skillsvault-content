# CRN-M-03 / D3 — Practice v1

## Назначение

Этот Practice проверяет не умение назвать «вероятную причину», а способность вести причинно-диагностический анализ поверх уже замороженной механики D1/D2.

Во всех кейсах запрещено превращать учебную гипотезу в root cause, inspection verdict, решение о браковке/ремонте/возврате в работу или разрешение эксплуатации. Если различение гипотез требует опасного воспроизведения отказа, перегруза, намеренного скольжения, заклинивания, регулировки или обхода защиты — правильный ход состоит в формулировке требуемого факта и STOP, а не в придумывании процедуры.

Learner-facing язык — русский. Английские метки допустимы только как уже объяснённые или необязательные синонимы.

---

## Обязательный формат ответа

Для каждого кейса дай минимум:

```text
1. OBSERVATION — что действительно наблюдалось / записано.
2. INFERENCE — что уже является интерпретацией.
3. UNKNOWN — чего не хватает.
4. H1 / H2 / ... — механически различимые гипотезы, если неуникальность остаётся.
5. Для каждой H — что меняется в D2-модели:
   тело / ССТ / ЦТ / контакт / loaded-state связи / active branches / holding / transient.
6. PREDICTION — какой различающий признак следует из механизма при одинаковых релевантных условиях.
7. EVIDENCE CHECK — наблюдаемость, соответствие условий, независимость от спорной модели, временное покрытие.
8. MODEL UPDATE — что усилилось, ослабло, исключено или осталось открытым.
9. SOURCE / AUTHORITY — какой источник способен дать нужный факт и чего он НЕ доказывает.
10. BOUNDED CONCLUSION / STOP — что можно утверждать сейчас без повышения статуса.
```

Не нужно искусственно выдумывать вторую гипотезу, если точное evidence действительно уже устранило причинную неуникальность. Но разные названия деталей не считаются разными гипотезами, если механическая модель и prediction у них одинаковые.

# Case A — «После обслуживания захват начал поворачиваться»

После планового обслуживания оператор сообщил: «после обслуживания захват стал сам поворачиваться». Есть запись в журнале: обслуживание выполнено утром; вечером того же дня при одном из подъёмов наблюдался поворот примерно на четверть оборота. Других подробностей журнал не содержит. На текущей стоянке без груза вертлюг вращается рукой свободно.

Сотрудник предлагает вывод: «при обслуживании ослабили вертлюг — это причина».

Задание:

1. Перепиши исходные данные так, чтобы observation не содержал причины.
2. Назови, какие части фразы сотрудника являются inference.
3. Построй несколько механически различимых причинных гипотез, если данных недостаточно для уникальной модели. Среди допустимых направлений анализа могут быть ЦТ, loaded-state сочленения, изменение контакта/удержания, последовательность включения ветвей или переходный процесс — но не ограничивайся названиями деталей.
4. Для каждой выбранной гипотезы укажи, что именно должно измениться в D2-модели.
5. Сформулируй prediction, которое различает хотя бы две гипотезы при одной и той же релевантной конфигурации.
6. Объясни, почему свободное вращение без нагрузки не закрывает loaded-state вопрос.
7. Сформулируй bounded conclusion без root-cause verdict.

# Case B — Три гипотезы с одной скрытой предпосылкой

Для случая перекоса подвески группа записала:

- H1: причина — смещённый центр тяжести груза;
- H2: причина — неравномерное распределение нагрузки по трём ветвям;
- H3: причина — ограниченная свобода сочленения под нагрузкой.

Во всех трёх расчётных схемах группа молча предполагает, что центральная ветвь уже находится в контакте и несёт нагрузку с самого начала подъёма. Фактический момент её включения не наблюдался.

Задание:

1. Оцени, действительно ли H1/H2/H3 независимы в текущем виде.
2. Назови common-mode premise — общую непроверенную предпосылку, способную испортить все три модели одновременно.
3. Покажи, как изменятся D2-модели, если центральная ветвь:
   - активна с начала;
   - включается после относительного перемещения;
   - вообще не включается в рассматриваемом состоянии.
4. Сформулируй evidence, которое различает именно состояние включения ветви, а не просто ещё раз фиксирует перекос.
5. Не вычисляй численное распределение нагрузки, пока модель активных контактов не закрыта.
6. Дай bounded conclusion.

# Case C — «Различающие» predictions при разных исходных условиях

Наблюдается боковой уход захвата при начале подъёма.

Группа сравнивает две модели:

- H1: смещение вызвано положением ЦТ;
- H2: смещение вызвано ограничением loaded-state сочленения.

Для H1 prediction взято из подъёма груза конфигурации X с одной ориентацией захвата. Для H2 используется видео другого подъёма конфигурации Y, где груз был повернут, точки контакта отличались, а центральная ветвь была предварительно натянута.

Задание:

1. Объясни, почему наблюдаемые различия между X и Y ещё не являются различающим evidence для H1/H2.
2. Определи минимальный набор релевантных условий, которые должны быть сопоставимы или иметь доказанную переносимость.
3. Построй пару predictions так, чтобы различие следовало из механизма H1/H2, а не из смены исходной конфигурации.
4. Назови, какие unknowns D2-модели должны быть зафиксированы до сравнения.
5. Если точное condition-matched evidence недоступно, сформулируй STOP/evidence request без предложения опасного повторного подъёма.

# Case D — Отсутствующий признак на видео

После краткого рывка оператор заметил изменение ориентации подвески. Имеется видео с частотой 1 кадр/с, снятое сбоку; зона соединения частично закрыта грузом. На видео не видно момента проскальзывания или резкого поворота вертлюга.

Один аналитик говорит: «раз проскальзывания не видно, гипотезу скольжения можно исключить». Другой говорит: «раз поворота не видно, вертлюг точно не менял состояния».

Задание:

1. Раздели «признак не записан» и «события не было».
2. Для каждого предполагаемого отрицательного evidence оцени:
   - наблюдаемость;
   - временное разрешение;
   - геометрическую видимость;
   - соответствие условий prediction.
3. Покажи, какое отрицательное evidence действительно могло бы ослабить выбранную гипотезу.
4. Назови минимум две гипотезы, которые текущая запись всё ещё не различает.
5. Дай model status каждой гипотезе без ложного исключения.

# Case E — Круговое «подтверждение»

По текущему перекосу захвата инженерная таблица оценивает предполагаемое положение контактной результирующей. Для расчёта таблица использует модель, в которой именно смещение контактной результирующей считается причиной перекоса. Полученное расчётное значение затем приводят как доказательство: «таблица подтверждает, что результирующая смещена и поэтому гипотеза верна».

Отдельного измерения положения контактной зоны или распределения давления нет.

Задание:

1. Нарисуй логическую цепочку, показывающую circular evidence.
2. Отдели derived quantity, полученную из спорной модели, от независимого evidence.
3. Сформулируй минимум два способа получить discriminating fact концептуально, не изобретая опасную процедуру и не присваивая inspection authority.
4. Покажи, как та же наблюдаемая ориентация могла бы быть совместима с иной D2-моделью.
5. Дай bounded conclusion, в котором расчёт остаётся prediction/model output, а не подтверждением причины.

# Case F — Пустой журнал истории

Для одного съёмного грузозахватного устройства доступен электронный журнал за последние три месяца. В нём нет записей об ударе или перегрузке. Позже выясняется, что система регистрации записывает только события выше заданного порога и не фиксирует краткие потери натяжения, малые удары или ручные перестановки устройства. На текущем осмотре виден локальный след контакта, но время его появления неизвестно.

Задание:

1. Объясни, почему «в журнале нет события» не равно «события не было».
2. Определи coverage/quality boundary журнала: что он способен и не способен исключить.
3. Раздели current state, возможный transient event и accumulated history.
4. Построй конкурирующие причинные истории, совместимые с текущим следом, не объявляя ни одну фактической.
5. Назови evidence, которое могло бы реально уточнить временную последовательность.
6. Не превращай duty/history crane-level evidence в remaining-life или конкретную историю этого attachment без доказанной применимости.

# Case G — Loaded-state finding найден после симптома

Сначала был зарегистрирован эпизод бокового смещения груза. После остановки и снятия нагрузки специалист обнаружил, что одно сочленение двигается туже соседнего. Через час без нагрузки оно снова перемещается свободнее. Других loaded-state измерений до эпизода нет.

Команда предлагает: «тугое сочленение было причиной смещения».

Задание:

1. Построй как минимум две причинные стрелки:
   - ограничение сочленения → смещение;
   - смещение/контакт/нагрузка → изменённое состояние сочленения.
2. Укажи, какие temporal/mechanical facts различили бы cause и consequence.
3. Объясни, почему post-symptom finding не получает статус initiating cause автоматически.
4. Пересобери D2-модель для обеих стрелок.
5. Сформулируй prediction и evidence request без повторного создания опасного события.
6. Дай bounded conclusion.

# Case H — Конечное состояние известно, последовательность неизвестна

После подъёма на фотографии видно, что три ветви натянуты, подвеска стабилизировалась и груз висит с небольшим наклоном. Записи начальной фазы нет.

Предлагаются две истории:

- S1: сначала нагрузились крайние ветви, затем после перемещения включилась центральная;
- S2: сначала включилась центральная ветвь, затем из-за поворота догрузились крайние.

Обе истории могут привести к похожему конечному состоянию.

Задание:

1. Объясни, почему конечная фотография не выбирает S1 или S2 автоматически.
2. Для каждой последовательности укажи промежуточное D2-состояние: active contacts, constraints, возможный transient.
3. Сформулируй prediction, зависящее от порядка событий, а не только от конечной геометрии.
4. Назови temporal evidence с достаточным разрешением, которое реально различило бы последовательности.
5. Если такого evidence нет, зафиксируй обе истории как допустимые и сформулируй правильный model status.

# Case I — Сильные документы, но разные полномочия

Для конкретной подвески собраны:

- OEM-документ, точно идентифицирующий конфигурацию и штатное назначение компонентов;
- действующий документ formal proof для определённого элемента;
- запись inspection, где описано текущее наблюдаемое состояние в пределах своей процедуры;
- safe-use план для конкретной операции.

После одного необычного поворота груза менеджер говорит: «у нас четыре сильных документа, значит мы знаем root cause и можем подтвердить, что работать можно».

Задание:

1. Разложи четыре источника по параллельным authority lanes.
2. Для каждого назови, какой факт/решение он способен поддержать и чего он не доказывает.
3. Покажи, почему сумма сильных документов не создаёт отсутствующий causal bridge.
4. Сформулируй competing mechanical hypotheses для необычного поворота, используя документы только в их допустимой роли.
5. Определи, какое independent discriminating evidence всё ещё требуется для причинной модели.
6. Не выдавай operation permission или return-to-service conclusion из D3 Practice.

# Case J — Интегрированный causal-diagnostic capstone

Съёмное грузозахватное устройство с тремя ветвями поднимает асимметричный груз. В начале движения наблюдается краткий поворот и последующая стабилизация под небольшим углом. Известно следующее:

- точный ЦТ груза в рассматриваемой конфигурации не подтверждён;
- до нагружения вертлюг двигается свободно, loaded-state неизвестен;
- конечная фотография показывает три натянутые ветви, но последовательность их включения не записана;
- на одной контактной поверхности после события виден новый след, но неизвестно, причина это или следствие;
- оператор описывает подъём как «очень медленный»;
- журнал событий не показывает удара, но его порог/частота регистрации ограничены;
- OEM-документ точно определяет модель устройства, но не описывает текущий причинный эпизод;
- отдельная inspection-запись существует, но её scope не является root-cause investigation.

Три участника предлагают:

- H1: основной механизм — смещённый ЦТ;
- H2: loaded-state ограничение вертлюга;
- H3: запаздывающее включение центральной ветви с переходным перераспределением нагрузки.

Задание:

1. Составь чистый Observation / Inference / Unknown register.
2. Проверь H1/H2/H3 на механическую уникальность и common-mode hidden premises.
3. Для каждой H пересобери D2-модель и укажи, что именно должно отличаться.
4. Не считай слово «медленно» доказательством квазистатики; отдельно рассмотри transient начала движения.
5. Не назначай новый контактный след причиной только потому, что он обнаружен после события.
6. Построй condition-matched predictions для H1/H2/H3.
7. Ранжируй минимум три возможных evidence items по способности реально различить модели и отдельно укажи authority каждого источника.
8. После мысленного получения одного нового факта опиши, какие части моделей пришлось бы пересобрать. Не выдумывай сам факт как уже известный.
9. Сформулируй bounded conclusion: какая гипотеза может быть лучше поддержана, какие альтернативы остаются открыты, какой следующий факт нужен.
10. Укажи явный STOP там, где дальнейшее различение потребовало бы опасного диагностического эксперимента или чужой inspection/specialist/operation authority.

## Общие запреты для всех кейсов

Не использовать как shortcut:

- «после» → «из-за»;
- внешний вид → доказанный contact/load state;
- свободное движение без нагрузки → loaded-state свобода;
- пустой журнал → отсутствие события;
- отсутствие видимого признака → отсутствие механизма без observability;
- расчёт из спорной модели → independent evidence;
- ослабление H1 → доказательство H2;
- локальную qualitative sensitivity → глобальный закон;
- OEM + proof + inspection + safe-use → единый root-cause/operation verdict;
- STOP ANALYSIS → permission to continue operation.

Practice не содержит answer key. Следующий слой отдельно построит несколько допустимых reasoning paths и failure families.
