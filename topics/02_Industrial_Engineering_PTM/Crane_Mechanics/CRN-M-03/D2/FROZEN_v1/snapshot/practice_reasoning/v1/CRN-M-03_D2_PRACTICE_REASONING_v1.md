## Несколько допустимых траекторий прикладной механики для кейсов A–J

# Как пользоваться этим документом

Это **не единый ответник**.

D2 проверяет не совпадение с одной заранее записанной фразой, а способность построить механическую модель, показать её границы и не повысить статус вывода сильнее доказательной цепочки.

Рабочий маршрут:

```text
ВОПРОС
→ ВЫБРАННОЕ ТЕЛО
→ ССТ
→ СИЛЫ / РЕАКЦИИ / МОМЕНТЫ
→ ЛИНИИ ДЕЙСТВИЯ / ЦТ
→ СВЯЗИ / КОНТАКТ / СТЕПЕНИ СВОБОДЫ
→ РАСПРЕДЕЛЕНИЕ НАГРУЗКИ
→ ФИЗИКА УДЕРЖАНИЯ
→ РЕЖИМ ДВИЖЕНИЯ
→ СТАТУС МОДЕЛИ
→ ДАННЫЕ, КОТОРЫЕ РЕАЛЬНО РАЗЛИЧАЮТ МОДЕЛИ
→ ОГРАНИЧЕННЫЙ ВЫВОД / STOP / ПЕРЕДАЧА ДАЛЬШЕ
```

Русский технический эквивалент полностью достаточен. Английские labels не требуются для зачёта.

Сильные ответы могут различаться:

- выбранной границей системы;
- порядком промежуточных шагов;
- числом локальных ССТ;
- символическими обозначениями;
- тем, какой именно дополнительный факт ученик считает наиболее различающим две модели;
- финальным ограниченным выводом, если неопределённость реальна.

Но сильный ответ не имеет права перепрыгивать через guards:

```text
БОЛЬШАЯ ССТ СКРЫЛА ИНТЕРФЕЙС ≠ ИНТЕРФЕЙС НЕ НАГРУЖЕН
УРАВНЕНИЯ СХОДЯТСЯ ≠ МОДЕЛЬ СВЯЗИ ДОКАЗАНА
ВИДИМАЯ СИММЕТРИЯ ≠ РАВНОЕ РАСПРЕДЕЛЕНИЕ НАГРУЗКИ
ГЕОМЕТРИЧЕСКИЙ ЦЕНТР ≠ ЦЕНТР ТЯЖЕСТИ
СВОБОДЕН БЕЗ НАГРУЗКИ ≠ СВОБОДЕН ПОД НАГРУЗКОЙ
МЕДЛЕННО ДВИЖЕТСЯ ≠ КВАЗИСТАТИКА ДОКАЗАНА
ФИЗИКА УДЕРЖАНИЯ ПОНЯТНА ≠ НОМИНАЛЬНАЯ СПОСОБНОСТЬ ДОКАЗАНА
FORMAL PROOF / INSPECTION / SAFE USE ≠ ОДИН И ТОТ ЖЕ СТАТУС
```

Иногда правильная траектория заканчивается не числом, а статусом:

```text
МЕХАНИЧЕСКАЯ МОДЕЛЬ НЕ ЗАМКНУТА
```

с конкретным объяснением, **какие данные изменят вывод**. Это сильный D2-ответ, а не отказ думать.

# Кейс A — Большая ССТ и скрытый внутренний интерфейс

## Сильная траектория 1: от глобального равновесия к локальному телу

На большой ССТ всей подвешенной системы внутренние силы в пальце/серьге действительно не появляются как внешние. Это корректно для вопроса об общем равновесии системы.

Но вопрос заказчика локальный: может ли интерфейс изменить характер нагрузки при смещении груза. Значит границу нужно поменять.

Один разумный маршрут:

```text
ШАГ 1 — БОЛЬШАЯ ССТ
вес всей подвешенной системы
+ внешние реакции от верхних канатных ветвей
→ общий баланс системы

ШАГ 2 — ЛОКАЛЬНАЯ ССТ
выделить серьгу / палец / связанную деталь
→ силы в интерфейсе снова становятся внешними
→ появляется локальная геометрия и возможное плечо
```

На локальной ССТ направление реакции можно связывать с **реально подтверждённой моделью связи**. Например, идеализированный палец может ограничивать одни перемещения и позволять другие. Но нельзя назначать удобную одну осевую силу только потому, что так проще решить уравнение.

Если вопрос касается локального момента, нужны данные о:

- фактической линии действия передаваемой силы;
- геометрии пальца/серьги;
- расстояниях между линиями действия;
- возможных вторичных контактах;
- положении груза/ЦТ, которое меняет общий путь сил.

### Альтернативная допустимая траектория

Можно начать сразу с локального тела, если ученик объяснит, почему глобальная ССТ не отвечает на локальный вопрос. Большая ССТ тогда используется только как cross-check общего пути нагрузки.

### Данные, которые реально различают модели

- чертёж интерфейса;
- фактическое положение точек приложения/контактов;
- загруженная геометрия;
- документация по типу соединения.

### Ограниченный вывод

```text
Исчезновение интерфейса из большой ССТ означает только то,
что силы интерфейса внутренние для выбранной большой системы.
Оно не доказывает отсутствие локальной силы, момента или эксцентриситета.
Для локального вывода нужна отдельная ССТ и геометрия интерфейса.
```

### Типичные провалы

- `A-F1`: «внутренняя сила сократилась → элемента можно не анализировать»;
- `A-F2`: назначить реакцию по удобной оси без модели связи;
- `A-F3`: перейти от локальной механики сразу к strength/proof verdict;
- `A-F4`: не менять границу системы при смене вопроса.

# Кейс B — Центрально выглядящий контакт

## Сильная траектория: величина силы и линия действия — разные сведения

Если распределённый контакт заменяется одной результирующей `R`, это допустимая учебная идеализация только вместе с допущением о положении линии действия.

Полезно держать две символические модели:

```text
МОДЕЛЬ 1:
линия действия проходит через выбранную опорную точку
→ e = 0 для этой идеализации

МОДЕЛЬ 2:
линия действия смещена
→ e ≠ 0
→ появляется дополнительный момент R·e
```

Главный смысл не в вычислении конкретного `e`, а в чувствительности:

```text
если R примерно фиксирована,
то изменение e меняет момент линейно в учебной модели M = R·e
```

Фотография, на которой master link выглядит «по центру», не даёт карту контактного давления. Даже симметричный внешний контур не гарантирует центральную результирующую при деформации, перекосе или неодинаковом контакте.

### Альтернативная допустимая траектория

Можно оставить контакт распределённым и не вводить одну результирующую вообще. Тогда ученик честно говорит: для moment balance нужна интегральная информация о распределении давления или эквивалентная результирующая с подтверждённой линией действия.

### Данные, которые реально различают модели

- нагруженная геометрия;
- карта/оценка контактной зоны;
- измерения деформаций или положения;
- подтверждённая модель контакта.

### Ограниченный вывод

```text
D2 может показать, что неопределённость положения результирующей
непосредственно превращается в неопределённость момента.
D2 не имеет данных, чтобы объявить e = 0
или назначить допустимый численный эксцентриситет.
```

### Типичные провалы

- `B-F1`: «выглядит центрально → e = 0»;
- `B-F2`: забыть момент после смещения линии действия;
- `B-F3`: ввести allowable eccentricity без источника;
- `B-F4`: считать замену распределённого контакта точечной силой фактом, а не моделью.

# Кейс C — Геометрический центр против центра тяжести

## Сильная траектория: сначала масса и ЦТ выбранной системы

Если выбирается система «груз + траверса + зажимное устройство», общий вес действует через **общий центр тяжести**, а не через геометрический центр внешнего контура груза.

Для простейшей плоской двухреакционной модели:

```text
ΣFy = 0:
R1 + R2 = W_total

ΣM_about_point_1 = 0:
R2·L - W_total·x_CG = 0
```

Это не готовая формула для реального оборудования, а символическая демонстрация: реакции зависят от положения результирующего веса.

Если `x_CG` неизвестен, задача не выдаёт `R1 = R2` только потому, что точки подвеса геометрически симметричны.

Также даже при известном ЦТ простая двухреакционная модель может стать неполной, если:

- подвесы имеют разные направления;
- есть зазоры или неполное включение;
- ветви имеют существенно разные жёсткости;
- траверса деформируется;
- контакт/сочленение меняет кинематические ограничения.

### Альтернативная траектория

Можно выбрать отдельно груз и отдельно траверсу. Тогда ученик строит две связанные ССТ и показывает, как неизвестные интерфейсные силы передаются между ними. Это сильнее, если вопрос локализован на соединении.

### Данные, которые реально различают модели

- массы всех включённых элементов;
- положение индивидуальных ЦТ;
- точные координаты точек подвеса;
- состояние связей/зазоров.

### Ограниченный вывод

```text
Симметрия точек подвеса не доказывает равенство реакций,
если общий ЦТ выбранной системы не подтверждён в плоскости симметрии.
```

### Типичные провалы

- `C-F1`: геометрический центр = ЦТ;
- `C-F2`: игнорировать массу траверсы/захвата;
- `C-F3`: превратить вычисленные реакции в WLL/capacity verdict;
- `C-F4`: не указать, для какой именно системы рассчитан ЦТ.

# Кейс D — Вертлюг свободен рукой без нагрузки

## Сильная траектория: минимум две loaded-state hypotheses

Нужно разделить название детали и её фактическое состояние связи.

Минимум две гипотезы:

```text
H1 — ВРАЩАТЕЛЬНАЯ СТЕПЕНЬ СВОБОДЫ ЭФФЕКТИВНО СВОБОДНА ПОД НАГРУЗКОЙ
→ передача крутящего момента через эту связь в идеализации ограничена

H2 — ВРАЩЕНИЕ ЧАСТИЧНО / ПОЛНОСТЬЮ ОГРАНИЧЕНО ПОД НАГРУЗКОЙ
→ связь может передавать дополнительную реакцию-момент
→ точная величина и направление всё ещё не известны автоматически
```

Факт свободного вращения рукой без нагрузки поддерживает только наблюдение unloaded-state. Он не закрывает loaded-state.

Если связь заблокирована, нельзя сразу сказать «весь момент пошёл в крюк» или назначить конкретный момент. Сначала нужно определить всю систему связей, другие пути передачи и геометрию.

### Альтернативная допустимая траектория

Можно моделировать loaded-state как диапазон между идеальной свободой и полной блокировкой и спросить, какие выводы сохраняются в обоих крайних случаях. Это полезный robust check без выдумывания реального коэффициента трения в вертлюге.

### Данные, которые реально различают модели

- наблюдение вращения под репрезентативной нагрузкой в допустимом процессе;
- конструктивная документация;
- состояние/история узла;
- измерение относительного вращения/момента, если предусмотрено процессом.

### Ограниченный вывод

```text
Unloaded observation не доказывает loaded degree-of-freedom state.
До подтверждения допустимы как минимум несколько механических гипотез,
и D2 должен явно показать зависимость вывода от выбранной модели связи.
```

### Типичные провалы

- `D-F1`: «называется вертлюг → момент не передаёт»;
- `D-F2`: unloaded motion = loaded freedom;
- `D-F3`: blocked DOF = известный момент;
- `D-F4`: сделать inspection verdict из одной механической гипотезы.

# Кейс E — Три ветви и один зазор

## Сильная траектория: сначала определить класс задачи

Первый вопрос не «чему равны `R1`, `R2`, `R3`?», а:

```text
КАКИЕ ИЗ ТРЁХ ВЕТВЕЙ ВООБЩЕ АКТИВНО ПЕРЕДАЮТ НАГРУЗКУ В ЭТОМ СОСТОЯНИИ?
```

При текущих данных одна ветвь имеет зазор. Значит active-contact set не подтверждён.

Полезная классификация:

### Состояние A — набор активных ветвей известен и задача закрывается равновесием

Если конкретная идеализация действительно имеет достаточно независимых уравнений и подтверждённые связи, реакции могут быть найдены из равновесия.

### Состояние B — активные ветви известны, но распределение зависит от совместности

Тогда нужны, например:

- жёсткости тяг;
- деформации траверсы;
- податливость соединений;
- геометрическая совместность.

### Состояние C — неизвестен сам набор активных контактов

Зазор означает, что одна ветвь может включиться позже. Тогда до замыкания контакта эта реакция может быть иной или нулевой в выбранной идеализации; после включения система меняется.

Именно поэтому выражение:

```text
R1 = R2 = R3 = G/3
```

не следует из визуальной симметрии.

### Альтернативная допустимая траектория

Ученик может рассмотреть два сценария:

- ветвь 3 пока не включена;
- ветвь 3 включилась после деформации/перемещения.

И показать, что механическая система меняется между сценариями. Это сильный ответ даже без чисел.

### Данные, которые реально различают модели

- величина и знак зазора под нагрузкой;
- жёсткости ветвей;
- деформации траверсы;
- последовательность включения;
- фактические реакции/деформации, если доступны допустимые измерения.

### Ограниченный вывод

```text
При неизвестном active-contact state распределение нагрузки не доказано.
Геометрическая симметрия не заменяет сведения о зазорах, жёсткости и совместности.
```

### Типичные провалы

- `E-F1`: три ветви → G/3;
- `E-F2`: совпало число уравнений/неизвестных → контактная модель верна;
- `E-F3`: игнорировать зазор;
- `E-F4`: объявить задачу статически неопределимой только по числу опор без анализа ограничений.

# Кейс F — Известна масса приспособления

## Сильная траектория: физическая масса да, универсальная capacity-арифметика нет

В учебной механике собственный вес каждого подвешенного элемента физически участвует в общей силе тяжести.

Для выбранной системы можно записать символически:

```text
W_total = (m_g + m_t + m_a + ... )·g
```

если именно эти массы входят в выбранную подвешенную систему.

Это позволяет:

- сравнивать два механических сценария по общей массе;
- видеть, что attachment self-weight влияет на реакции;
- не забывать массу устройства в ССТ.

Но формула

```text
m_allow = Q - m_t - m_a
```

не становится универсальной только потому, что массы известны точно. `Q` без exact load chart/configuration/radius/mode/rules of attachment accounting — всего лишь неподтверждённый элемент для operational-capacity вопроса.

### Альтернативная допустимая траектория

Ученик может вообще не использовать `Q` в D2 mechanics packet и сказать: `Q` относится к следующему source/authority layer. В механической части сравниваются только силы/массы, а допустимость операции оставляется за exact equipment process.

### Данные, которые реально различают модели

- точная модель/конфигурация крана;
- применимый load chart;
- радиус/режим/оснастка;
- правила учёта attachments;
- совместимость интерфейсов;
- конкретные документы устройства.

### Ограниченный вывод

```text
D2 подтверждает, что собственная масса приспособлений участвует в механике системы.
D2 не подтверждает универсальную формулу вычитания из одной capacity-цифры
и не выдаёт operational permission.
```

### Типичные провалы

- `F-F1`: механическая масса → нормативная payload formula;
- `F-F2`: marking Q → exact current capacity;
- `F-F3`: забыть массу attachment на ССТ;
- `F-F4`: сделать safe-use verdict без exact equipment source.

# Кейс G — Фрикционный захват

## Сильная траектория: причинная модель не равна подтверждённому устройству

Минимальная учебная картина может содержать:

- внешнюю нагрузку на груз;
- нормальные реакции челюстей;
- касательные контактные силы, связанные с фрикционным механизмом удержания;
- геометрию контакта;
- возможные внутренние силы механизма, если они известны.

Но общий список факторов из урока — это **карта причин**, а не исчерпывающий device-specific checklist.

Неизвестными могут оставаться:

- реальная кинематика зажима;
- самозажимание;
- внутреннее передаточное отношение;
- preload/замыкание механизма;
- состояние шарниров;
- допустимые поверхности/ориентации;
- exact geometry range;
- manufacturer-defined exclusions.

Если выясняется, что есть геометрическое самозажимание, простая модель «нормальная сила задана извне» может быть неверной: сама нормальная сила зависит от геометрии и внутренней механики.

### Альтернативная допустимая траектория

Вместо попытки закрыть holding force ученик может построить causal graph:

```text
внешняя нагрузка
→ внутренняя кинематика захвата
→ нормальная реакция
→ доступная фрикционная составляющая
→ удержание
```

и отметить все неизвестные переходы.

### Данные, которые реально различают модели

- exact model/device documentation;
- принцип действия и кинематическая схема;
- manufacturer-defined conditions;
- состояние механизма, подтверждаемое применимым процессом.

### Ограниченный вывод

```text
D2 может классифицировать предполагаемый механизм удержания
и показать, от каких состояний он зависит.
Без exact-device данных нельзя превращать эту модель
в holding rating, acceptance или разрешение применения.
```

### Типичные провалы

- `G-F1`: перечислены факторы → удержание доказано;
- `G-F2`: придумать μ или clamping force;
- `G-F3`: игнорировать неизвестную внутреннюю кинематику;
- `G-F4`: causal checklist = inspection checklist.

# Кейс H — «Очень медленно» и выбирание слабины

## Сильная траектория: разделить процесс по состояниям

Минимум три этапа:

```text
1. ДО ВЫБОРА СЛАБИНЫ
часть ветвей может не нести ту же нагрузку, что после включения

2. МОМЕНТ / ИНТЕРВАЛ ВЫБОРА СЛАБИНЫ
контактное состояние меняется
возможны локальные ускорения / ударное включение / перераспределение реакций

3. ПОСЛЕ УСТАНОВИВШЕГОСЯ НАТЯЖЕНИЯ
при достаточно медленном и плавном движении
квазистатическая модель может стать разумной гипотезой,
но это нужно обосновать для конкретного вопроса
```

Малая **средняя скорость** не ограничивает автоматически локальное ускорение в переходе. Поэтому фраза «поднимаем медленно» не доказывает `ΣF = 0` на всём процессе.

Если нужен динамический уровень, `ΣF = m·a` закрывает только поступательную часть выбранного тела. Для жёсткого тела с вращением может понадобиться моментное уравнение вида:

```text
ΣM = I·α
```

в подходящей модели и с подтверждёнными параметрами. D2 не вводит нормативный dynamic factor.

### Альтернативная допустимая траектория

Можно не строить полноценную динамическую модель, а выполнить status downgrade:

```text
установившийся медленный участок — возможно квазистатическая гипотеза
переход при выборе слабины — квазистатика не доказана
```

и запросить данные только для переходного участка.

### Данные, которые реально различают модели

- временная история движения;
- ускорение;
- натяжение/реакции во времени;
- величина слабины;
- жёсткость системы;
- длительность перехода.

### Ограниченный вывод

```text
D2 может качественно показать, что выбирание слабины меняет контактное состояние
и способно изменить реакции по сравнению с установившейся квазистатикой.
Без данных нельзя назначить нормативный коэффициент динамичности.
```

### Типичные провалы

- `H-F1`: малая скорость = a≈0 всегда;
- `H-F2`: применять ΣF=0 в момент включения контакта без проверки;
- `H-F3`: ΣF=m·a = полная динамика жёсткого тела;
- `H-F4`: придумать dynamic factor.

# Кейс I — Три зелёных документа

## Сильная траектория: разделить роли доказательств

Три фрагмента относятся к разным вопросам:

```text
FORMAL PROOF КРЮКА
→ говорит о том, что доказано для конкретного объекта/объёма применимого proof-процесса

INSPECTION ЗАХВАТА
→ говорит о результате конкретной проверки/инспекции в её scope

SAFE-USE PLAN
→ относится к организации/планированию конкретного безопасного применения
```

Ни один слой не автоматически закрывает остальные.

Могут оставаться открытыми:

- совместимость интерфейсов;
- actual loaded geometry;
- положение ЦТ;
- распределение реакций;
- состояние сочленений;
- exact device holding conditions;
- применимость каждого документа к текущей конфигурации.

### Альтернативная допустимая траектория

Ученик может построить матрицу «вопрос → какой документ на него отвечает → что остаётся вне scope». Это хороший способ не смешивать evidence roles.

### Данные, которые реально различают модели

Не «ещё один любой сертификат», а конкретные gap-closing items:

- exact configuration identity;
- interface documentation;
- applicable proof record для нужного компонента/состояния;
- inspection scope/result для нужного устройства;
- safe-use plan для конкретной операции;
- OEM/source данные, если механический вопрос зависит от device-specific конструкции.

### Ограниченный вывод

```text
Наличие нескольких положительных документов уменьшает некоторые неопределённости,
но не создаёт автоматически whole-system proof или разрешение конкретного подъёма.
D2 mechanics conclusion остаётся ограниченным своим вопросом и моделью.
```

### Типичные провалы

- `I-F1`: component proof = whole-system proof;
- `I-F2`: inspection = design/proof;
- `I-F3`: safe-use plan = holding proof;
- `I-F4`: SkillsVault выносит operational verdict.

# Кейс J — Интегрированный D2 capstone

## Шаг 1 — Разделить decision questions

Минимум три разных вопроса, например:

1. **Как механически распределяется вес между ветвями в текущем состоянии?**
2. **Как loaded-state вертлюга и положение ЦТ влияют на реакции/моменты?**
3. **Доказано ли удержание захватом и допустима ли конкретная операция?**

Первый и второй — mechanics questions. Третий сразу включает source/authority layers, которые D2 одной общей механикой не закрывает.

## Шаг 2 — Две полезные границы системы

### Граница A — вся подвешенная система

На ССТ появляются:

- общий вес системы через неизвестный общий ЦТ;
- внешние реакции от верхней части подвеса;
- при соответствующей границе — возможно и другие внешние воздействия.

Эта ССТ нужна для общего баланса, но скрывает локальные силы внутри тяг/захвата/вертлюга.

### Граница B — локальный узел

Можно выбрать:

- одну тягу и её соединение;
- вертлюг;
- захват + груз;
- master link в крюке.

Тогда соответствующие интерфейсные силы становятся внешними и можно анализировать локальную геометрию.

## Шаг 3 — Register линий действия и ЦТ

Неизвестны как минимум:

- точный ЦТ груза;
- общий ЦТ системы;
- линия действия результирующей контакта master link/крюк;
- возможные линии реакций при разных loaded-state вертлюга;
- фактические реакции в трёх ветвях.

`почти по центру` не заменяет измерение/модель.

## Шаг 4 — Loaded-state вертлюга

Минимум:

```text
H1: вращение эффективно свободно под нагрузкой
H2: вращение частично/полностью ограничено под нагрузкой
```

Нужно показать, какие реакции/моменты разрешены в каждой модели. Нельзя переносить unloaded observation напрямую.

## Шаг 5 — Три ветви

Из-за зазора сначала неизвестен active-contact set.

Возможные стадии:

```text
до включения третьей ветви
→ одна модель распределения

после включения
→ другая модель
→ может потребоваться совместность / жёсткость / деформации
```

`G/3` не следует из рисунка.

## Шаг 6 — Захват

Предполагаемый holding principle можно классифицировать как фрикционный/зажимной **только как рабочую гипотезу**, пока exact model не идентифицирована.

Неподтверждёнными остаются:

- exact mechanism;
- internal transmission/self-locking;
- contact conditions;
- allowable orientations/surfaces;
- manufacturer conditions;
- current device state.

## Шаг 7 — Движение и слабина

«Очень медленно» относится к средней/наблюдаемой скорости. Но момент выбора слабины — изменение контактного состояния.

Нужно отдельно отметить:

```text
установившийся участок — возможно квазистатическая гипотеза
переход включения — квазистатика не доказана
```

## Шаг 8 — Status-promotion traps

Минимум:

- mechanics → formal proof;
- visual symmetry → equal load share;
- unloaded articulation → loaded DOF;
- slow motion → proven quasistatics;
- visible marking → current capacity;
- general source → exact applicability;
- inspection/history → operational permission.

## Шаг 9 — Какие данные сильнее всего изменят модель

Хороший learner не пишет просто «нужна документация». Он ранжирует сведения по тому, какие ветви модели они закрывают.

Сильный набор может быть:

1. **точная идентификация захвата + его документация** — меняет holding model/source role;
2. **фактический ЦТ груза/системы** — меняет реакции и моменты;
3. **loaded-state вертлюга** — меняет constraint model;
4. **зазоры/жёсткости/деформации трёх ветвей** — меняют load-share;
5. **данные по переходному процессу** — меняют dynamic-model status;
6. **точная конфигурация/применимый equipment source** — нужна для capacity/safe-use вопросов.

Порядок может быть другим, если ученик объяснит, какой decision question приоритетен.

## Шаг 10 — Ограниченный итог

Один сильный вариант:

```text
Текущий пакет позволяет построить несколько полезных D2 механических моделей,
но не замыкает единственную модель реальной системы:
не подтверждены ЦТ, active-contact/load-share state,
loaded-state вертлюга, exact holding mechanism и переходная динамика.

Поэтому нельзя выводить равные реакции, центральную результирующую,
доказанную квазистатику, holding rating, capacity compatibility
или разрешение конкретной операции.

Следующий шаг — собрать перечисленные различающие данные
и передать соответствующие вопросы в exact source/OEM/inspection/safe-use process.
```

### Допустимая альтернативная траектория

Ученик может начать с decision-question matrix и для каждого вопроса строить отдельную ССТ/модель. Это даже предпочтительно, если он явно избегает одной «универсальной» модели, которая смешивает механический, proof и operational вопросы.

# Cross-case failure taxonomy — кандидаты на Expected Result

Эти семейства **не объявляются здесь автоматически non-compensable blocking failures**. Их тяжесть должен решить будущий Verification Rubric.

## `RF-D2-01 — BODY / INTERFACE LAUNDERING`

Большая граница системы используется, чтобы скрыть локальный интерфейс и объявить его механически несущественным.

## `RF-D2-02 — FORCE / MOMENT MAP INCOMPLETE`

Ученик закрывает `ΣF`, но теряет materially relevant момент, линию действия или внешнюю реакцию.

## `RF-D2-03 — CONTACT RESULTANT INVENTION`

Положение результирующей контакта назначается по виду/симметрии без evidence.

## `RF-D2-04 — CG SUBSTITUTION`

Центр тяжести заменяется геометрическим центром или ЦТ неполной системы.

## `RF-D2-05 — CONSTRAINT-STATE PROMOTION`

Unloaded поведение сочленения объявляется доказанным loaded-state.

## `RF-D2-06 — LOAD-SHARE BY APPEARANCE`

Симметрия/число ветвей превращаются в равные реакции без closure contact/compatibility/stiffness model.

## `RF-D2-07 — CAPACITY ARITHMETIC PROMOTION`

Общая механика масс/сил превращается в универсальную equipment-capacity формулу.

## `RF-D2-08 — HOLDING COMPLETENESS CLAIM`

Общий causal model или список факторов объявляется полным device-specific verification/acceptance.

## `RF-D2-09 — QUASISTATIC PROMOTION`

Низкая скорость или «плавность на глаз» превращаются в доказанную квазистатику переходного процесса.

## `RF-D2-10 — EVIDENCE-ROLE / AUTHORITY COLLAPSE`

Formal proof, inspection, safe use, маркировка, история или общий источник смешиваются в один operational verdict.

## `RF-D2-11 — NON-DISCRIMINATING EVIDENCE REQUEST`

Вместо запроса данных, которые реально различают модели, ученик пишет общее «нужна документация» и не показывает, какой gap закрывается.

# Что должно перейти в Expected Result

Expected Result должен проверить наблюдаемое поведение, а не способность повторить этот текст.

Минимальные кандидаты:

1. выбрать границу системы по decision question;
2. построить полную ССТ и не потерять materially relevant моменты;
3. отделить известную величину силы от неизвестной линии действия;
4. вести ЦТ как доказательный параметр, а не геометрическую догадку;
5. строить несколько loaded-state constraint hypotheses при недостатке данных;
6. правильно классифицировать load-share problem;
7. отделять физику общей массы от equipment-specific capacity logic;
8. отделять holding physics от rating/acceptance;
9. различать установившуюся квазистатику и переходный процесс;
10. разделять mechanics / formal proof / inspection / safe use / equipment authority;
11. формулировать данные, которые реально различают модели;
12. завершать bounded conclusion или STOP, если модель не замкнута.

Known Practice A–J должны быть обязательны для обучения, но **не достаточны для transfer verification**. Будущий Rubric должен добавить unseen case.

# Финальный D2 reasoning self-check

Перед сильным выводом спроси:

1. Моя граница системы отвечает именно на текущий вопрос?
2. Не спрятал ли я внутренний интерфейс, который важен локально?
3. Все materially relevant силы и моменты есть на ССТ?
4. Положение результирующей контакта действительно известно?
5. ЦТ подтверждён для выбранной системы?
6. Loaded-state связей доказан, а не перенесён из unloaded observation?
7. Active-contact / совместность / жёсткость достаточны для load-share?
8. Holding model точно относится к идентифицированному устройству?
9. Квазистатика относится к нужному участку процесса?
10. Я не превратил механику в formal proof/inspection/safe-use verdict?
11. Запрашиваемые данные реально изменят одну из конкурирующих моделей?
12. Мой вывод не сильнее доказательной цепочки?

Если любой ответ «нет», сильный D2-ответ должен **понизить статус модели**, а не замаскировать пробел красивым числом.
