# 1. Главная идея

Эксперт должен уметь связать:

```text
КАК КРАН БЫЛ РАССЧИТАН РАБОТАТЬ
+
КАК ОН РЕАЛЬНО РАБОТАЛ
+
КАКУЮ ЛОКАЛЬНУЮ ИСТОРИЮ ПОЛУЧИЛ КАНАТ / ЦЕПЬ
+
ЧТО ПОКАЗЫВАЕТ ТЕКУЩИЙ КОНТРОЛЬ
```

Но эти четыре слоя нельзя считать одним и тем же.

Главный guard G8:

```text
РЕЖИМ РАБОТЫ КРАНА
≠
ЛОКАЛЬНАЯ ИСТОРИЯ КАНАТА
≠
ОСТАТОЧНЫЙ РЕСУРС КАНАТА
```

# 5. «Один цикл» — только начало вопроса

Рабочий цикл крана является глобальной единицей службы.

Но для каната один цикл крана может включать:

- несколько проходов через блоки;
- изгиб;
- обратный изгиб;
- изменение натяжения;
- переход между слоями барабана;
- разные длины активного участка.

Поэтому:

```text
1 ЦИКЛ КРАНА
```

не означает автоматически:

```text
1 ЦИКЛ ИЗГИБА КАЖДОЙ ПРОВОЛОКИ
```

---

# 6. Одинаковое число циклов — разная история каната

Два крана могут выполнить по 100 000 рабочих циклов.

Но канаты получат разную историю, если различаются:

- высота подъёма;
- схема запасовки;
- число блоков;
- наличие обратного изгиба;
- средняя масса груза;
- спектр грузов;
- доля работы на верхних / нижних отметках;
- одно- или многослойный барабан;
- положение переходных зон.

### D4-вывод

Глобальная статистика:

```text
N_crane
```

должна быть преобразована в локальную модель истории элемента, прежде чем использовать её для объяснения повреждения.

---

# 7. Средняя нагрузка может скрывать тяжёлую историю

Два режима могут иметь одинаковую среднюю массу груза.

Но:

```text
РЕЖИМ A
много средних грузов

РЕЖИМ B
много лёгких + немного очень тяжёлых
```

могут иметь разные:
- спектры;
- амплитуды;
- контактные состояния;
- усталостную тяжесть.

Поэтому:

```text
СРЕДНЕЕ
```

не заменяет:

```text
СПЕКТР
```

---

# 8. И спектр нагрузки ещё не вся история

Даже одинаковый спектр грузов не задаёт полностью историю каната.

Нужны ещё:

```text
ПЕРЕМЕЩЕНИЯ
+
ПОЛОЖЕНИЕ
+
ПОСЛЕДОВАТЕЛЬНОСТЬ
+
ГЕОМЕТРИЯ СИСТЕМЫ
```

Один и тот же груз может:
- пройти через один блок;
- пройти через несколько блоков;
- попасть в переход многослойного барабана;
- не попасть туда вовсе.

# 9. Локальная история элемента

Для D4 вводится учебная модель `LOCAL DUTY MAP`.

Это не нормативная классификация.

Для каната:

```text
КООРДИНАТА x
+
НАТЯЖЕНИЕ T(t)
+
КРИВИЗНА κ(t)
+
КОНТАКТ C(t)
+
КРУТИЛЬНОЕ СОСТОЯНИЕ R(t)
+
СРЕДА E(t)
+
ЧИСЛО ПРОХОДОВ
```

Для цепи:

```text
ГРУППА ЗВЕНЬЕВ
+
РАБОЧАЯ ВЫСОТА
+
КОНТАКТ С КОЛЕСОМ
+
ДИНАМИКА
+
РЕВЕРС
+
СМАЗКА
+
ЦИКЛЫ
```

# 10. Глобальный режим → локальная история

Экспертный переход:

```text
КЛАСС / РЕЖИМ КРАНА
↓
ФАКТИЧЕСКИЙ DUTY
↓
ДВИЖЕНИЯ МЕХАНИЗМА
↓
КООРДИНАТА ЭЛЕМЕНТА
↓
ЛОКАЛЬНЫЕ МЕХАНИЧЕСКИЕ СОБЫТИЯ
↓
ПОВРЕЖДЕНИЕ
```

Нельзя перескакивать:

```text
КЛАСС КРАНА
→
РЕСУРС КАНАТА = X
```

без валидированной модели.

# 13. Расчётный рабочий период ≠ гарантийный таймер

Опасная логика:

```text
ДО РАСЧЁТНОГО ПРЕДЕЛА ЕЩЁ ДАЛЕКО
→
ЗНАЧИТ СОСТОЯНИЕ ХОРОШЕЕ
```

неверна.

Расчётный рабочий период:
- относится к проектной / эксплуатационной модели системы;
- не отменяет текущее фактическое повреждение.

И обратная ошибка:

```text
ПРИБЛИЖАЕМСЯ К РАСЧЁТНОМУ ПРЕДЕЛУ
→
ЗНАЧИТ КАНАТ УЖЕ НЕГОДЕН
```

тоже неверна без применимого критерия состояния.

---

# 14. Мониторинг не заменяет инспекцию

ISO 12482 связывает мониторинг службы с фокусированием / корректировкой инспекций.

То есть:

```text
МОНИТОРИНГ DUTY
```

отвечает:

> где и когда нужно внимательнее проверять?

А:

```text
ИНСПЕКЦИЯ
```

отвечает:

> в каком состоянии объект сейчас?

Это разные функции.


---

# 19. Что регистратор может НЕ знать о канате

В зависимости от системы он может хранить:
- массу / нагрузку;
- время;
- движения;
- события.

Но локальная механическая история каната может дополнительно требовать:

- координату конкретного участка;
- какой блок он проходил;
- слой барабана;
- переходную зону;
- фактический диаметр;
- локальный контакт;
- монтажную историю.

Поэтому:

```text
DATA LOGGER
≠
DIGITAL TWIN OF ROPE
```

# 20. Событие, цикл и повреждающее событие

D4 разделяет:

## Рабочий цикл крана
Функциональная единица работы.

## Событие механизма
Подъём, опускание, разгон, торможение, реверс.

## Локальное повреждающее событие
Например:
- проход через конкретный блок;
- обратный изгиб;
- пересечение переходной зоны;
- контакт с соседним витком.

Эти счётчики могут отличаться на порядки.

---

# 21. Последовательность тоже важна

Спектр часто описывает распределение.

Но реальная история имеет порядок:

```text
лёгкий
лёгкий
тяжёлый
лёгкий
...
```

и:

```text
тяжёлый
тяжёлый
тяжёлый
...
```

могут одинаково выглядеть в агрегированной статистике, но давать разные:
- контактные состояния;
- пластические эпизоды;
- последствия первого повреждения.

### Guard

D4 не объявляет sequence-effect универсальным без конкретной модели.

Он учит не терять временную структуру там, где она физически значима.

---

# 22. Повреждение меняет дальнейшую duty-модель

Если появились:
- износ;
- обрыв;
- сплющивание;
- изменение шага;
- деформация,

то одинаковый следующий рабочий цикл действует уже на **другую систему**.

Поэтому:

```text
DUTY HISTORY
+
DAMAGE EVOLUTION
```

образуют связанную задачу.

# 23. Приближение к расчётному пределу — повод изменить вопрос

Когда usage monitoring показывает приближение к расчётной границе, эксперт должен спросить:

```text
КАКИЕ ОБЛАСТИ СТАНОВЯТСЯ КРИТИЧЕСКИМИ?
КАКИЕ ИНСПЕКЦИИ НУЖНО УСИЛИТЬ?
КАКИЕ ИСХОДНЫЕ ДАННЫЕ НУЖНЫ ДЛЯ REVIEW?
КАКИЕ РЕШЕНИЯ ТРЕБУЮТ ПРОЕКТИРОВЩИКА / ЭКСПЕРТА?
```

Не:

> «просто продолжать до числа X».

---

# 24. История службы ≠ автоматическое продление ресурса

Наличие хорошего monitoring dataset:
- повышает качество экспертного анализа;
- может поддерживать специальные проверки;
- помогает понять фактический duty.

Но само по себе:

```text
НЕ ДАЁТ
```

автоматического права:
- продлить ресурс;
- изменить проектный срок;
- отменить инспекцию;
- игнорировать критерий браковки элемента.

---

# 25. Ресурс крана ≠ ресурс каната

Особенно важно для CRN-M-01.

Канат:
- расходный / заменяемый элемент;
- имеет собственную историю;
- может быть заменён несколько раз за жизнь крана.

Следовательно:

```text
CRANE DESIGN WORKING PERIOD
```

и:

```text
ROPE SERVICE LIFE
```

не являются одной шкалой.

---

# 26. Новый канат на старом кране

После замены:

```text
КАНАТ
→ новая локальная история
```

но:

```text
БАРАБАН
БЛОКИ
ГЕОМЕТРИЯ
РЕЖИМ
КРАН
```

остаются с собственной старой историей.

Поэтому recurring damage после replacement может быть мостом между:
- локальной историей нового каната;
- глобальной историей старой системы.

---

# 27. Данные эксплуатации как естественный эксперимент

Если после изменения:
- маршрута;
- диапазона высоты;
- технологического цикла;
- характера грузов

меняется координата / скорость повреждения, это может дать сильное причинное evidence.

Но D4 требует:
- убедиться, что изменение разрешено;
- не менять эксплуатацию ради эксперимента без полномочий;
- учитывать сопутствующие изменения.

# 29. Уровни уверенности

## H0
Есть только заявленный класс / режим.

## H1
Есть фактические записи эксплуатации.

## H2
Есть распределение нагрузок / движений.

## H3
Есть связь с координатой каната / цепи.

## H4
Есть повторяемая локальная история + инспекция.

## H5
Есть source-bound модель, связывающая duty с конкретным расчётным выводом.

Это учебная лестница SkillsVault, не норматив.

---

# 30. Когда данных недостаточно

Правильный D4-ответ может быть:

> «Известен режим работы крана, но неизвестны фактическая высота подъёма и координата переходов каната; этого недостаточно для локальной усталостной модели.»

Это сильнее, чем:

> «режим тяжёлый, значит канат устал».

# 32. Инспекционный приоритет

История duty может менять:

```text
ГДЕ СМОТРЕТЬ
КАК ЧАСТО ПЕРЕПРОВЕРЯТЬ
КАКОЙ МЕТОД ДОБАВИТЬ
```

в пределах применимой процедуры.

Но D4 не должен самовольно создавать новый обязательный интервал инспекции без нормативного / OEM основания.

---

# 33. Глобальный «тяжёлый режим» не локализует дефект

Если весь кран работает тяжело, это ещё не объясняет:

> почему повреждение стабильно возникает на 37-м метре каната.

Для локализации нужны:
- геометрия;
- положение;
- переход;
- история движения.

---

# 34. Локальный дефект может возникнуть при умеренном глобальном duty

Если существует локальный усилитель:

- плохой ручей;
- перекос;
- crossover;
- неверная цепь;
- изношенное колесо;
- монтажный twist.

Поэтому:

```text
GLOBAL DUTY MODERATE
```

не оправдывает игнорирование локального механизма.

ISO/CD 12482 применён как действующий стандарт.

История эксплуатации автоматически продлевает ресурс.

## RF-G8-10
Глобальная тяжесть режима выдана за доказанную локальную причину.

- exact special-inspection intervals;
- official life extension;
- residual-life number;
- legal/formal approval.
