# CRN-M-01 — D3
# Verification Evidence Model v1

## Зачем

D3-компетенция и сила доказательства — разные оси.

```text
D3
=
глубина навыка

V
=
насколько сильно подтверждено, что человек этим навыком владеет
```

---

# V0 — NOT VERIFIED

Человек:
- прочитал;
- отметил тему;
- возможно считает, что понял.

Доказательства выполнения нет.

---

# V1 — SELF-ATTESTED

Человек самостоятельно утверждает:

> «Я это умею».

Может иметь:
- заметки;
- самооценку;
- чек-лист.

Независимой проверки нет.

---

# V2 — STRUCTURED PRACTICAL EVIDENCE

Для D3 требуется:

- выполнен минимум один интегрированный кейс H-уровня;
- есть письменный или структурированный ход рассуждения;
- сохранены модели;
- предсказания;
- различающие данные;
- ограниченный вывод.

V2 означает:

> **есть воспроизводимый артефакт практической работы, пригодный для проверки.**

V2 ещё не означает, что работа обязательно правильная.

---

# V3 — AI-REVIEWED

Требуется:

- evidence уровня V2;
- проверка по текущей D3 Verification Rubric;
- итог `PASS`;
- сохранён балл;
- сохранены замечания;
- сохранена версия рубрики;
- сохранена дата / проверяющий агент;
- нет критических ошибок.

V3 означает:

> **структурированная практическая работа прошла AI-проверку по явной рубрике.**

---

# V4 — HUMAN / EXPERT REVIEWED

Требуется:

- evidence V2;
- проверка человеком / экспертом;
- та же D3-рубрика или эквивалентная по требованиям;
- `PASS`;
- сохранён provenance;
- замечания и область проверки.

V4 не означает D4.

V4 означает:

> **D3-компетенция подтверждена более сильным проверяющим.**

---

# V5 — REAL-WORLD / FORMAL EVIDENCE

Возможные доказательства:

- реальный производственный кейс;
- формальное рабочее задание;
- документированный анализ;
- реальный осмотр / измерения;
- результат, принятый в рабочем процессе;
- формальная аттестация в своей области.

V5 всегда scope-specific.

Нельзя записывать:

> «V5 по канатам вообще»

если реальное доказательство касалось только одного узкого типа оборудования.

---

# Обязательный provenance

Каждая запись verification должна хранить:

```text
topic_id
depth
competency_scope
evidence_id
evidence_type
reviewer_type
rubric_version
score
critical_errors
result
date
source_artifact
notes
status
```

---

# Статусы evidence

- VALID
- STALE
- REQUIRES_RECHECK
- SUPERSEDED
- REVOKED

История не перезаписывается.

Новая проверка создаёт новую запись.

---

# Когда evidence становится STALE

Например:

- сильно изменилась нормативная база;
- изменился метод проверки;
- компетенция долго не применялась;
- область оборудования изменилась;
- обнаружена ошибка в исходном evidence.

STALE не означает:

> «человек всё забыл».

Это означает:

> **сила текущего доказательства снизилась.**

---

# Минимум для D3 freeze компетенции

Контент может быть заморожен независимо.

Но для подтверждения конкретного учащегося D3:

```text
минимум:
V2 evidence
+
rubric review
```

Для утверждения «проверено системой»:

```text
V3
```

Для сильного внешнего подтверждения:

```text
V4 / V5
```
