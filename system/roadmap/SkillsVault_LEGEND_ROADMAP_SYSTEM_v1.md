# SkillsVault — Legend Roadmap System

Version: 1.0  
Date: 2026-08-31  
Status: CANONICAL DESIGN PROPOSAL  
Applies to: all learning domains, all courses/routes, all Topics

---

# 1. Product intent

SkillsVault must support a learner entering any discipline from literal zero and progressing, step by step, to extreme professional depth.

The system must never force a false choice between:

- simple, understandable teaching; and
- genuinely deep professional material.

Instead, depth is layered and earned.

Core rule:

> Do not remove difficult knowledge to make learning accessible. Explain it when the learner has enough prior understanding to make it meaningful.

The target experience is:

```text
I know almost nothing
        ↓
I understand the basic picture
        ↓
I can use it with support
        ↓
I can work independently
        ↓
I can analyse difficult cases
        ↓
I can design / diagnose / review
        ↓
I can integrate disciplines, challenge assumptions, teach others,
work from primary sources and contribute new understanding
```

The final stage is called **LEGEND** as a motivational product label. It does not mean infallibility or omniscience. It means demonstrated, unusually deep and integrative capability within the defined scope.

---

# 2. Two independent axes

SkillsVault must not confuse **content depth** with **personal mastery**.

## Axis A — Topic depth

Every Topic is authored in progressive layers.

### D1 — Базовый / Понять

Purpose: build the mental model.

The learner should be able to explain the subject in ordinary language, understand why it matters, identify the main objects/processes and avoid the most dangerous misconceptions.

### D2 — Средний / Применять

Purpose: turn understanding into practical capability.

Adds professional terminology, typical parameters, measurements, diagnostic logic, calculations where useful, realistic cases and routine decision making.

### D3 — Продвинутый / Анализировать

Purpose: handle complexity and non-obvious cases.

Adds deeper physical/mathematical models, interacting failure mechanisms, uncertainty, competing hypotheses, design trade-offs, limitations of simplified models, advanced diagnostics and primary technical sources.

### D4 — Экспертный справочный слой / Reference

Purpose: support real professional work and very deep study.

May include standards, OEM-specific requirements, detailed tables, derivations, uncommon edge cases, special methods, verification procedures, advanced references and source maps.

D4 is not necessarily read linearly. It is a working knowledge layer connected to the teaching sequence.

---

## Axis B — Personal capability

A learner's mastery is assessed independently of what content exists.

Suggested route-scale:

```text
R0 — Ноль
R1 — База
R2 — Практик
R3 — Самостоятельный специалист
R4 — Продвинутый
R5 — Эксперт
R6 — ЛЕГЕНДА
```

### R0 — Ноль

No assumed domain knowledge beyond everyday literacy/numeracy required by the route.

### R1 — База

Can explain core concepts, recognize major components/processes and follow basic reasoning.

### R2 — Практик

Can solve standard tasks with checklists, examples, documentation or guidance.

### R3 — Самостоятельный специалист

Can perform routine professional work independently, justify decisions and recognize when escalation is required.

### R4 — Продвинутый

Can diagnose difficult cases, compare models, work with uncertainty, integrate adjacent topics and detect hidden assumptions.

### R5 — Эксперт

Can design/review complex solutions, work directly with primary sources and standards, challenge weak reasoning, mentor others and make high-consequence judgements within scope.

### R6 — ЛЕГЕНДА

Can synthesize multiple disciplines, reason in novel and ambiguous situations, identify limitations of accepted approaches, build new methods/models/routes, teach at multiple levels, perform high-quality technical review, and contribute reusable knowledge back to the system.

R6 requires evidence. Reading all advanced material is not sufficient.

---

# 3. Every course has a Zero-to-Legend Roadmap

Every meaningful learning direction must have its own roadmap.

A roadmap is not just an ordered Topic list. It defines:

- entry assumptions;
- milestones R0–R6;
- required competencies at each milestone;
- mandatory and optional Topics;
- Topic depth required at each milestone;
- prerequisite branches;
- cross-domain dependencies;
- practice/evidence required for promotion;
- Project Gates;
- expert/reference material;
- capstones;
- Legend-level synthesis challenges.

The roadmap must answer at every stage:

1. Where am I?
2. What can I already do?
3. What should I learn next?
4. Why is that next step now understandable?
5. What new abilities will it unlock?
6. What evidence proves I am ready to move on?

---

# 4. Every Topic is progressively layered

All course lessons must follow the same progressive-depth philosophy.

A mature Topic should expose, where applicable:

```text
Topic
├── D1 Базовый — понять
│   ├── зачем это знать
│   ├── простая модель
│   ├── ключевые объекты и причинность
│   └── базовые ошибки мышления
│
├── checkpoint D1
│
├── D2 Средний — применять
│   ├── профессиональная терминология
│   ├── параметры / измерения
│   ├── типовые задачи
│   ├── диагностика
│   └── производственные кейсы
│
├── checkpoint D2
│
├── D3 Продвинутый — анализировать
│   ├── глубокая теория
│   ├── математика / модели
│   ├── сложные отказы
│   ├── неопределённость и границы применимости
│   └── междисциплинарный анализ
│
└── D4 Reference
    ├── нормативы
    ├── OEM
    ├── первичные источники
    ├── подробные методики
    └── редкие/пограничные случаи
```

Not every Topic must have equal volume at every depth. A small Topic may keep D3 concise and link to a dedicated deep Topic rather than duplicate an entire discipline.

However, the user-facing learning path must never end simply because the old file happened to be short.

---

# 5. Complexity is earned, not hidden

Progression must follow:

```text
meaning
→ intuition
→ terminology
→ mechanism
→ measurement
→ quantitative model
→ practical application
→ diagnosis / design
→ limitations
→ synthesis
→ original contribution
```

A formula must appear because it answers a question the learner already understands.

A technical term must appear because the learner already has a concept to attach it to.

A standard must appear when the learner understands what decision the standard constrains.

---

# 6. Roadmap promotion is evidence-based

Promotion between roadmap stages is not granted by reading percentage alone.

Examples of evidence:

- explain a mechanism in own words;
- solve representative calculations;
- identify components on real equipment;
- diagnose from incomplete evidence;
- produce an inspection/check plan;
- analyse a failure;
- review a technical decision;
- compare alternative designs;
- work with an OEM manual or primary standard;
- complete a project/capstone;
- teach the concept clearly;
- identify uncertainty and missing evidence;
- integrate multiple disciplines in one decision.

At higher levels, evidence should increasingly be open-ended and realistic.

---

# 7. Legend is a synthesis level

Legend must never mean "memorized everything".

A Legend-level learner should demonstrate five properties:

## 7.1 Depth

Can go from intuitive explanation to first-principles/primary-source reasoning within the domain.

## 7.2 Breadth

Understands the important neighbouring systems that change the answer.

## 7.3 Judgement

Can reason under uncertainty, recognize insufficient evidence and avoid false certainty.

## 7.4 Transfer

Can solve unfamiliar cases rather than only repeat practiced patterns.

## 7.5 Contribution

Can improve the knowledge system itself: teach, review, document, design better methods, identify missing Topics, or create reusable professional knowledge.

Legend is therefore a moving frontier, not a permanent claim of perfection.

---

# 8. Curiosity-driven detours

Roadmaps must support side branches without losing the learner.

Example:

```text
CRN-M-01 Канаты
   ↓
"Почему проволока ломается после множества изгибов?"
   ↓
Fatigue / усталость материалов
   ↓
"Почему диаметр блока влияет на ресурс?"
   ↓
изгиб + геометрия + контакт
   ↓
возврат в Crane Mechanics уже на более глубоком уровне
```

The system should remember both:

- the main route the learner was following; and
- the newly learned supporting branch.

Curiosity is not a distraction. It is one of the navigation engines of SkillsVault.

# 9. Current Vault-wide direction map

Canonical v0.51 currently contains 16 major learning domains and 138 first-level branches (excluding Project_Gates).

Each must eventually receive a Zero-to-Legend Roadmap.

## 01 — Software Engineering

Legend target: independently design, implement, test, operate and critically review production software systems; reason across algorithms, Linux, networking, databases, security, distributed architecture and delivery.

## 02 — Industrial Engineering / PTM

Legend target: understand lifting equipment as an integrated mechanical-electrical-control-safety system; diagnose, inspect, reason about maintenance and documentation, evaluate technical solutions and make evidence-based decisions under applicable regulations/OEM constraints.

## 03 — Electrical & Electronics

Legend target: reason from basic voltage/current to real power, sensing, electronics, control and embedded systems; measure safely, diagnose faults and review system-level electrical decisions.

## 04 — Engineering Design

Legend target: turn a need into a defensible engineered design using physics, calculations, drawings, materials, manufacturing constraints, verification and iteration.

## 05 — English

Legend target: confidently consume, produce and discuss complex professional/technical information; work directly with primary English-language technical sources and communicate nuance precisely.

## 06 — Meta Professional

Legend target: learn efficiently, research rigorously, communicate decisions, execute projects and continuously improve one's own professional system.

## 07 — Industrial Automation & Drives

Legend target: understand and commission/control industrial systems across sensors, signals, PLCs, networks, drives, HMI/SCADA, interlocks, diagnostics and safety boundaries.

## 08 — Reliability & Maintenance Engineering

Legend target: build and improve maintenance/reliability systems using condition monitoring, vibration, lubrication, failure analysis, RCM/FMEA, planning, lifecycle and evidence-based strategy.

## 09 — Mechanical Engineering / Machine Design

Legend target: reason from statics/dynamics and strength to fatigue, tribology, gears, bearings, tolerances, materials, FEA and verified machine design.

## 10 — Industrial Safety & Risk Engineering

Legend target: identify hazards, analyse risk, design/control barriers, investigate incidents, reason about human factors and verify safety decisions without confusing compliance with actual risk control.

## 11 — Technical Procurement & Lifecycle

Legend target: translate needs into requirements, evaluate technical equivalence/deviations, qualify suppliers, analyse lifecycle/TCO, verify FAT/SAT/commissioning and defend procurement decisions technically.

## 12 — Software Engineering Extended

Legend target: operate across additional languages/platforms, frontend/mobile/data/automation stacks and integrate them into robust production solutions.

## 13 — DevOps & Infrastructure Engineering

Legend target: design, secure, deploy, observe, recover and evolve production infrastructure from Linux/networking through TLS, containers, Kubernetes/cloud/IaC and incident response.

## 14 — AI Engineering / LLM Systems

Legend target: design and evaluate reliable AI/LLM systems across prompting/context, RAG, tool calling, agents, security, cost, evaluation, observability and human-in-the-loop production design.

## 15 — System Design / Product / Technical Leadership

Legend target: translate ambiguous product/business needs into system boundaries, architecture, trade-offs, roadmaps and delivery decisions; lead rigorous technical reviews across stakeholders.

## 16 — Aviation / Aircraft Engineering

Legend target: integrate aerodynamics, structures, propulsion, systems, avionics, flight mechanics, maintenance, certification, safety and aircraft design into defensible engineering reasoning.

For each stage define:

- competencies;
- mandatory Topics;
- required depth D1–D4;
- optional specializations;
- prerequisite branches;
- Project Gates;

- newly unlocked branches.

# 11. Branch roadmaps

The same philosophy applies below the domain level.

Example:

```text
Mechanical Engineering
└── Fatigue & Fracture
    ├── R0: what repeated loading means
    ├── R1: stress, cycles, cracks
    ├── R2: basic fatigue assessment
    ├── R3: real component diagnosis
    ├── R4: mean stress, notches, spectrum loading, uncertainty
    ├── R5: advanced assessment / standards / fracture mechanics
    └── R6: integrate material, geometry, manufacturing, inspection,
            loading history and risk into novel engineering decisions
```

Thus "roadmap of every direction" exists at several scales:

```text
Vault
→ Domain
→ Branch / specialization
→ Route
→ Topic
→ Depth layer
→ Practice / Evidence
```

# 12. Content authoring impact

The current one-pass batch model is obsolete for hardened content.

For each Topic:

1. define capability;
2. audit prerequisites;
3. audit sources;
4. build mental model;
5. design layered D1–D4 structure;
6. write D1;
7. review D1;
8. write D2;
9. review D2;
10. write D3;
11. review D3;
12. build/reference D4;
13. design layered practice;
14. define evidence/mastery expectations;
15. graph audit;
16. red team;
17. human learning review;
18. freeze Topic.

Batch remains only a packaging/integration unit.

# 13. Application implications — request, not implementation

This design implies future application support for:

- Topic depth layers D1–D4;
- route levels R0–R6;
- separate content-depth vs personal-mastery state;
- visible prerequisite readiness;
- "what this unlocks";
- side-branch navigation with return-to-route;
- milestone/gate evidence;
- roadmap visualization;
- partial depth completion per Topic;
- expert/reference sections that do not distort normal beginner progression.

These are application requirements only. The CONTENT workstream must not change application code or production schemas directly.

A formal schema/application change request should be produced during CQ2/CQ3 before implementation.

# 14. Definition of success

SkillsVault succeeds when a learner can select any major direction and truthfully see a path like:

```text
I know nothing about this
        ↓
I understand enough to keep going
        ↓
I can do useful things
        ↓
I can work independently
        ↓
I can reason about difficult cases
        ↓
I can review/design/teach
        ↓
I can connect the discipline to the rest of engineering/professional knowledge
        ↓
I can contribute new high-quality knowledge myself
```

No arbitrary ceiling is imposed on depth.

The system stops adding depth only when additional material no longer meaningfully improves understanding, capability, judgement, source access or cross-disciplinary synthesis.
